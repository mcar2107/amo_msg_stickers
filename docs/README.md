# Дока amo stickers

Сайт пользовательской документации на VitePress: https://mcar2107.github.io/amo_msg_stickers/ — на русском (корень
сайта) и английском (https://mcar2107.github.io/amo_msg_stickers/en/).

Отдельный пакет pnpm со своим lockfile — зависимости сайта не попадают в сборку расширения.

## Команды

Из корня репозитория:

```bash
pnpm -C docs i       # зависимости доки (нужны и для pnpm typecheck)
pnpm docs:dev        # локально: http://localhost:5173/amo_msg_stickers/
pnpm docs:build      # сборка в docs/.vitepress/dist, битая ссылка — ошибка сборки
pnpm docs:preview    # просмотр собранного сайта
```

## Что где

```
content/     страницы: адрес — путь файла без .md
  en/        английские страницы: те же пути, что у русских, адрес — /en/ и путь
  _parts/    общие фрагменты, подключаются <!--@include: …--> и отдельными страницами не собираются
    en/      английские фрагменты
  img/       скрины и демо, общие для обоих языков
public/      статика: логотип для шапки, главной и иконки вкладки
.vitepress/
  config.mts языки (locales): навигация, сайдбар и подписи темы у каждого свои; база адреса, поиск
  theme/     тема по умолчанию + цвета amo (style.css) + вкладки ::::tabs
```

## Правила текста

- Правка страницы — в обоих языках одним PR: русская `content/<путь>.md` и английская `content/en/<путь>.md`.
  Страница без пары на другом языке роняет тест `tests/userDocsPages.test.ts`.
- Новая страница — файл в `content/` и в `content/en/` и пункт в `sidebar` обеих локалей в `config.mts`; пункт
  сайдбара называется как H1 страницы.
- Ссылки между страницами — относительные: из `en/` они остаются внутри английской доки.
- Картинки английских страниц — те же файлы из `content/img/`, путь на уровень глубже: `../img/` → `../../img/`,
  `./img/` → `../img/`. Копий не делаем, `alt` пишем по-английски.
- Адреса страниц `setup/gif-keys` и `setup/telegram` открывает интерфейс на своём языке (`src/core/userDocs.ts`):
  переименование без правки кода ломает тест.
- Место под скрин — комментарий `<!-- скрин: img/<раздел>/<имя>.png — что на нём -->`. Готовый скрин кладётся в
  `content/img/<раздел>/`, комментарий заменяется картинкой.
- Скрин — PNG, пожатый `pngquant`, без личных данных: чужие имена, чаты, ключи и токены размываются до вставки.
  Узкий высокий кадр (экран телефона, окно Telegram) вставляется тегом `<img src="…" alt="…" width="400">`, иначе
  тема растянет его на всю ширину страницы.
- Адрес, который сайт открыть не может (`chrome://extensions` и подобные), — `<CopyCode text="…" />`: браузер
  не пускает на такие адреса по ссылке, поэтому он копируется по клику.
- Тексты проходят typograf символами Unicode (неразрывный пробел, «», —), без HTML-сущностей; английские — с
  локалью `en-US`. Typograf прогоняется по тексту, а не по файлу целиком: целиком он ломает markdown (`- ` списков,
  `::::tabs`, `../` путей). Неразрывные пробелы, которые он ставит внутри `code`, после прогона убираются.

## Публикация

Сайт публикуется за новым релизом: `release.yml` вызывает `.github/workflows/pages.yml` из коммита релиза, и сайт не
описывает ещё не выпущенное. Мерж в `master` с правками в `docs/` без релиза сайт не меняет. Правку о выпущенном
поведении публикует ручной запуск — `gh workflow run pages.yml --ref master`; он берёт весь `master`, поэтому только
когда в нём нет правок доки о невыпущенном.
В PR сборку проверяет задание `docs`.
