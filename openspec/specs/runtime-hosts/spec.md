# runtime-hosts Specification

## Purpose

Определяет окружения, в которых работает расширение (браузерное MV3-расширение и userscript), а также единые правила сетевых запросов и хранения настроек в них.

## Requirements

### Requirement: Браузерное расширение
Система SHALL поставляться как Chrome MV3-расширение, которое запускается на страницах `https://*.amo.tm/*`, `http://localhost:3000/*` и `http://127.0.0.1:3000/*`. Расширение MUST запрашивать только разрешение `storage` и доступ к хостам GIPHY, KLIPY и Telegram API. Manifest расширения MUST нести публичный ключ карточки Chrome Web Store, поэтому ID расширения SHALL быть одним и тем же — `abjnjphijggkkdbbmkldhibgepgdcgip` — при установке из Chrome Web Store и при загрузке распакованного архива из любой папки. На тех же страницах расширение MUST подключать агент в мире страницы (требование «Агент в мире страницы»).

#### Scenario: Установка распакованного расширения
- **WHEN** пользователь загружает `dist/extension` как распакованное расширение и открывает web.amo.tm
- **THEN** в поле ввода появляется кнопка стикеров, в консоли страницы строка `[amo-stickers] started (extension)`

#### Scenario: ID архива совпадает с ID из стора
- **WHEN** пользователь загружает распакованный архив из релиза на странице расширений браузера
- **THEN** у расширения ID `abjnjphijggkkdbbmkldhibgepgdcgip` — тот же, что у версии из Chrome Web Store

#### Scenario: Распаковка в другую папку сохраняет настройки
- **WHEN** пользователь сохранил ключ GIPHY и, не удаляя расширение из браузера, загрузил архив новой версии из другой папки
- **THEN** ID расширения не меняется, и в «Настройках» стоит сохранённый ранее ключ GIPHY

#### Scenario: Агент расширения
- **WHEN** расширение установлено и открыт чат amo
- **THEN** стикер уходит через очередь amo, а в списке разрешений расширения нет новых пунктов

### Requirement: Сетевые запросы в обход CORS страницы
Запросы к внешним API и CDN SHALL выполняться в обход CORS страницы, чтобы не зависеть от CORS-заголовков сервисов: в расширении — из фонового service worker, в userscript — через сетевой API менеджера userscript-ов (`GM_xmlhttpRequest` или `GM.xmlHttpRequest`). Ошибки HTTP MUST возвращаться в интерфейс с кодом статуса и началом тела ответа. Запросы userscript через API менеджера MUST уходить без cookie целевых сайтов. Заголовок userscript MUST перечислять в `@connect` только хосты сетевой политики: `api.telegram.org`, `giphy.com`, `klipy.com`.

#### Scenario: Telegram без CORS
- **WHEN** Telegram API не отдаёт CORS-заголовки
- **THEN** импорт в расширении всё равно работает

#### Scenario: Скачивание файла стикера Telegram в userscript
- **WHEN** в userscript, установленном в Tampermonkey, пользователь импортирует пак Telegram, а ответ на скачивание файла стикера (`api.telegram.org/file/bot…`) приходит без `Access-Control-Allow-Origin`
- **THEN** файлы стикеров скачиваются, импорт доходит до конца, импортированный стикер отправляется в чат

#### Scenario: Ошибка HTTP в userscript
- **WHEN** запрос userscript через API менеджера получает ответ со статусом 404
- **THEN** операция завершается ошибкой, текст которой содержит `HTTP 404` и начало тела ответа

#### Scenario: Сетевая политика в userscript
- **WHEN** userscript запрашивает адрес вне сетевой политики либо ответ API менеджера пришёл с итоговым адресом вне политики после редиректа
- **THEN** запрос завершается ошибкой «Адрес вне списка разрешённых», данные ответа ядру не передаются

#### Scenario: Лимит размера в userscript
- **WHEN** userscript скачивает файл с лимитом, а тело ответа больше лимита (с `Content-Length` или без него)
- **THEN** загрузка обрывается, не дочитывая остаток, операция завершается ошибкой «Файл больше N МБ»

### Requirement: Userscript
Система SHALL поставляться как самодостаточный userscript (`dist/amo-stickers.user.js`) с тем же поведением, что и расширение. Он работает в менеджерах userscript-ов (Tampermonkey и т. п.). В менеджере, который это поддерживает, userscript MUST выполняться в изолированном мире, а не в мире страницы: скрипты страницы MUST NOT получать доступ к коду ядра, к API менеджера и к настройкам. В мир страницы MUST попадать только агент (требование «Агент в мире страницы»). Если скрипт подключён на страницу без менеджера и API менеджера недоступно, userscript MUST работать через прямой `fetch` со страницы и `localStorage`. Повторное подключение скрипта на той же странице MUST NOT создавать второй экземпляр ни ядра, ни агента.

#### Scenario: Запуск в менеджере userscript-ов
- **WHEN** пользователь устанавливает скрипт в Tampermonkey и открывает web.amo.tm
- **THEN** в поле ввода появляется кнопка стикеров, в консоли строка `[amo-stickers] started (userscript)`

#### Scenario: Изоляция от страницы
- **WHEN** скрипт страницы amo обращается к `GM_xmlhttpRequest`, `GM_getValue` или к глобальным объектам userscript
- **THEN** они для него не определены

#### Scenario: Подключение без менеджера
- **WHEN** `dist/amo-stickers.user.js` подключён на страницу напрямую, без менеджера userscript-ов
- **THEN** кнопка стикеров появляется, сетевые запросы идут прямым `fetch` со страницы, настройки хранятся в `localStorage`

#### Scenario: Двойное подключение
- **WHEN** скрипт подключён на странице дважды
- **THEN** у каждого поля ввода по-прежнему одна кнопка стикеров, один клик по стикеру отправляет одно сообщение

#### Scenario: Отправка через очередь в менеджерах
- **WHEN** userscript установлен в Tampermonkey или Violentmonkey, в поле ввода набран текст, и пользователь кликает на стикер
- **THEN** стикер уходит через очередь amo, текст в поле остаётся

#### Scenario: Агент не выполнился
- **WHEN** агент не выполнился в мире страницы (менеджер или политика страницы не пустили его)
- **THEN** стикер при пустом поле уходит запасным путём, вставкой в поле

### Requirement: Настройки
Система SHALL хранить ключ GIPHY, ключ KLIPY и токен Telegram-бота на экране «Настройки» в хранилище окружения: `chrome.storage.local` в расширении, хранилище менеджера userscript-ов (`GM_getValue` / `GM_setValue`) в userscript, `localStorage` в userscript без менеджера. Если в userscript с менеджером хранилище менеджера пусто, а в `localStorage` есть настройки, сохранённые прежней версией, они MUST быть перенесены в хранилище менеджера при первом чтении и удалены из `localStorage`. Встроенный ключ KLIPY и встроенный токен Telegram-бота сборки MUST NOT показываться в полях «Настроек» и MUST NOT попадать в хранилище: поля — только для своих значений пользователя.

Поля MUST идти двумя группами: «GIF» — ключ KLIPY, затем ключ GIPHY, с пояснением; «Telegram» — токен бота. Без встроенного ключа KLIPY пояснение группы «GIF» MUST говорить, что для поиска GIF достаточно одного из двух ключей; со встроенным — что поиск KLIPY работает без ключа, а ключ GIPHY добавляет источники GIPHY. На экране MUST быть одна строка о том, что ключи и токен хранятся только в этом браузере. Поля MUST быть скрыты как пароль, у каждого поля MUST быть кнопка «Показать» / «Скрыть», которая показывает значение открытым текстом и обратно, с состоянием в дереве доступности.

Кнопки «Сохранить» нет: изменённое значение MUST сохраняться при уходе фокуса из поля, по Enter в поле, по «Назад», при переключении режима и при закрытии попапа. Несохранённый ввод MUST NOT теряться ни одним из этих путей. Значения сохраняются без пробелов по краям; пустое значение — отсутствие ключа. Удачная запись MUST NOT показывать статус: принято ли значение, говорит проверка у поля; ошибка записи MUST показываться в строке статуса. новые значения MUST применяться без перезагрузки страницы. Футера с кнопкой у экрана «Настройки» нет.

#### Scenario: Порядок полей
- **WHEN** пользователь открывает «Настройки» в сборке без встроенного ключа KLIPY
- **THEN** в группе «GIF» сверху вниз ключ KLIPY и ключ GIPHY и сказано, что хватит одного; ниже группа «Telegram» с токеном бота

#### Scenario: Пояснение группы со встроенным ключом
- **WHEN** пользователь открывает «Настройки» в сборке со встроенным ключом KLIPY
- **THEN** в группе «GIF» сказано, что поиск KLIPY работает без ключа, а ключ GIPHY добавляет источники GIPHY; поле KLIPY пустое

#### Scenario: Встроенный ключ не сохраняется
- **WHEN** пользователь сборки со встроенным ключом KLIPY открывает «Настройки», уходит из пустого поля KLIPY и нажимает «Назад»
- **THEN** ключа KLIPY в хранилище нет, поиск KLIPY работает по встроенному ключу

#### Scenario: Сохранение ключа GIPHY
- **WHEN** пользователь вводит ключ GIPHY, нажимает «Назад» и открывает режим «GIF»
- **THEN** показана трендовая выдача GIPHY без перезагрузки страницы

#### Scenario: Ключ из пустого режима GIF
- **WHEN** в режиме «GIF» без ключей пользователь нажимает «Открыть настройки», вставляет ключ KLIPY и нажимает «Назад»
- **THEN** открыт режим «GIF» с трендами KLIPY

#### Scenario: Закрытие попапа с правкой
- **WHEN** пользователь вводит ключ KLIPY и, не уходя из поля, закрывает попап Escape, затем открывает его снова
- **THEN** в поле введённый ключ, и он сохранён в хранилище

#### Scenario: Показать ключ
- **WHEN** пользователь нажимает «Показать» у ключа GIPHY
- **THEN** ключ виден открытым текстом, кнопка называется «Скрыть» и отмечена нажатой

#### Scenario: Перенос настроек из localStorage
- **WHEN** пользователь обновляет userscript в менеджере, а токен бота и ключи GIF были сохранены прежней версией в `localStorage` amo
- **THEN** на экране «Настройки» те же значения, импорт и поиск GIF работают без повторного ввода, а ключ настроек в `localStorage` amo удалён

#### Scenario: Настройки недоступны странице
- **WHEN** пользователь userscript с менеджером сохраняет токен бота
- **THEN** токена нет в `localStorage` amo

### Requirement: Метаданные на двух языках
Описание расширения SHALL быть на русском и английском: браузер показывает его в списке расширений на своём языке
интерфейса, а для языка без перевода — русское описание, как запасной язык amo. Название расширения («amo stickers»)
MUST быть одинаковым на обоих языках. Заголовок userscript MUST содержать описание по умолчанию на русском и его
английский вариант для менеджеров, которые выбирают описание по языку. Zip расширения из релиза и из сборки PR MUST
содержать переводы описания.

#### Scenario: Расширение в английском Chrome
- **WHEN** пользователь с английским интерфейсом Chrome устанавливает расширение из zip релиза
- **THEN** в списке расширений название «amo stickers» и описание на английском

#### Scenario: Расширение в немецком Chrome
- **WHEN** интерфейс Chrome на немецком
- **THEN** описание расширения на русском

#### Scenario: Userscript в менеджере
- **WHEN** пользователь с английским браузером устанавливает userscript в Tampermonkey
- **THEN** в окне установки описание на английском

### Requirement: Автообновление userscript
Заголовок userscript из боевой сборки SHALL содержать `@updateURL` и `@downloadURL`, указывающие на файл userscript
последнего релиза: `https://github.com/mcar2107/amo_msg_stickers/releases/latest/download/amo-stickers.user.js`.
Userscript dev-сборки (`pnpm watch`) MUST NOT содержать этих директив: менеджер не должен заменять его версией из релиза.

#### Scenario: Вышла новая версия
- **WHEN** в Tampermonkey установлен userscript из релиза, а в репозитории вышел релиз с большей версией
- **THEN** проверка обновлений в Tampermonkey находит и ставит новую версию

#### Scenario: Dev-сборка
- **WHEN** разработчик ставит в менеджер userscript из `pnpm watch`
- **THEN** в его заголовке нет `@updateURL` и `@downloadURL`

### Requirement: Подсказки настроек
У ключа KLIPY подсказка на экране «Настройки» SHALL вести на страницу выдачи ключей Partner Panel
(`https://partner.klipy.com/api-keys`), у ключа GIPHY — на `https://developers.giphy.com/dashboard/`, у токена — на
@BotFather. У группы «GIF» и у группы «Telegram» MUST быть по одной ссылке на страницу доки с пошаговой инструкцией;
текст ссылки MUST NOT переноситься внутри слова. Если в сборке есть встроенный токен Telegram-бота, подсказка у токена
MUST говорить, что свой токен необязателен: импорт работает и без него, а свой бот нужен, если встроенный недоступен.
Без встроенного токена подсказка MUST говорить, что токен нужен для импорта. Если в сборке есть встроенный ключ KLIPY,
подпись поля KLIPY MUST говорить, что свой ключ необязателен, а подсказка — что поиск KLIPY работает и без него, а свой
ключ нужен, если встроенный недоступен. Без встроенного ключа подпись и подсказка поля KLIPY — о бесплатном тестовом
ключе, без слов о необязательности. Подсказки MUST быть на языке интерфейса,
ссылки на доку MUST вести на страницу доки на языке интерфейса: из английского — на английскую, из русского — на
русскую. Ссылки MUST открываться в новой вкладке.

#### Scenario: Где взять ключ KLIPY
- **WHEN** пользователь открывает «Настройки» и нажимает ссылку в подсказке ключа KLIPY
- **THEN** в новой вкладке открывается страница API-ключей Partner Panel KLIPY

#### Scenario: Подробная инструкция
- **WHEN** пользователь нажимает ссылку на доку в группе «Telegram»
- **THEN** в новой вкладке открывается страница доки об импорте из Telegram

#### Scenario: Одна ссылка на доку о ключах
- **WHEN** пользователь открывает «Настройки»
- **THEN** в группе «GIF» одна ссылка на доку о ключах GIF, а не по одной у каждого ключа

#### Scenario: Английский интерфейс
- **WHEN** интерфейс на английском, а пользователь нажимает ссылку на доку в группе «GIF»
- **THEN** подсказка на английском, текст ссылки не говорит о языке инструкции, открывается английская страница доки
  о ключах GIF

#### Scenario: Свой токен необязателен
- **WHEN** в сборке есть встроенный токен, и пользователь открывает «Настройки»
- **THEN** подсказка у токена говорит, что свой токен необязателен и нужен, если встроенный бот недоступен, со ссылкой
  на @BotFather

#### Scenario: Сборка без встроенного токена
- **WHEN** в сборке нет встроенного токена, и пользователь открывает «Настройки»
- **THEN** подсказка у токена говорит создать бота в @BotFather, без слов о необязательности

#### Scenario: Свой ключ KLIPY необязателен
- **WHEN** в сборке есть встроенный ключ KLIPY, и пользователь открывает «Настройки»
- **THEN** подпись поля KLIPY говорит, что ключ необязателен, подсказка — что поиск работает без него, а свой нужен, если
  встроенный недоступен, со ссылкой на Partner Panel

#### Scenario: Сборка без встроенного ключа KLIPY
- **WHEN** в сборке нет встроенного ключа KLIPY, и пользователь открывает «Настройки»
- **THEN** подсказка у поля KLIPY — о бесплатном тестовом ключе в Partner Panel, без слов о необязательности

### Requirement: Иконки
Расширение SHALL объявлять иконки 16, 32, 48 и 128 px в `icons` manifest, userscript — иконку 48 px в `@icon`, встроенную
data URI: менеджеру не нужно загружать её по сети. Иконки MUST попадать в сборку расширения.

#### Scenario: Иконка в списке расширений
- **WHEN** пользователь открывает `chrome://extensions` после установки расширения
- **THEN** у карточки amo stickers — иконка amo stickers, а не заглушка браузера

#### Scenario: Иконка в менеджере userscript-ов
- **WHEN** пользователь ставит боевой userscript в Tampermonkey
- **THEN** в списке скриптов у amo stickers — иконка amo stickers

### Requirement: Иконка кнопки по теме браузера
Кнопка расширения на панели браузера SHALL показывать светлую иконку в светлой теме браузера и тёмную — в тёмной. Тему
MUST сообщать content script страницы amo (`prefers-color-scheme`): при загрузке и при каждой смене темы. Иконка MUST
ставиться для всех вкладок. До первого сообщения о теме, в том числе без открытой вкладки amo, MUST стоять светлая
иконка из manifest. Service worker MUST принимать сообщение о теме только от content script-а своего расширения. Клик по
кнопке ничего не открывает.

#### Scenario: Тёмная тема браузера
- **WHEN** в браузере тёмная тема и открыта вкладка amo
- **THEN** кнопка расширения на панели — с тёмной иконкой

#### Scenario: Смена темы на лету
- **WHEN** пользователь меняет тему браузера при открытой вкладке amo
- **THEN** иконка кнопки меняется без перезагрузки вкладки

#### Scenario: Вкладки amo нет
- **WHEN** браузер запущен, а вкладка amo ещё не открыта
- **THEN** у кнопки расширения светлая иконка

### Requirement: Агент в мире страницы
Внутренний путь отправки amo доступен только скриптам страницы, поэтому в мире страницы SHALL выполняться агент, который
умеет одно: отправить переданный ему файл отдельным сообщением в открытый чат amo — ответом на сообщение, если в поле
ввода этого чата активен ответ, — и после отправки снять этот ответ. Агент MUST NOT отдавать странице и вызывающей
стороне ничего, кроме статуса команды и причины отказа: ни код ядра, ни API менеджера, ни настройки, ни содержимое поля
ввода, ни сообщение, на которое отвечают. Команды агенту видны скриптам страницы; через агента страница MUST NOT
получать возможностей сверх тех, что у неё уже есть, — отправить файл в открытый чат ответом и снять ответ она может и
сама.

#### Scenario: Посторонняя команда
- **WHEN** скрипт страницы шлёт агенту команду в неверном формате
- **THEN** агент ничего не отправляет и не отвечает

#### Scenario: Ответ не раскрывает черновик
- **WHEN** агент отправил стикер при тексте в поле ввода и активном ответе на сообщение
- **THEN** в его ответах нет текста поля, вложений, настроек и сообщения, на которое отвечают, — только статус

### Requirement: Проверка ключей и токена
После сохранения изменённого непустого ключа GIPHY или KLIPY система SHALL проверить его одним запросом к API
источника и показать результат у поля: ключ работает; ключ не принят — источник ответил отказом в доступе (HTTP 401
или 403, у KLIPY ещё и 404: им он отвечает на неверный ключ); не удалось проверить — любая другая ошибка, в том числе недоступность сети. Изменённый непустой токен
Telegram-бота SHALL проверяться только по формату `<цифры>:<строка>`, без запросов; токен другого вида — предупреждение
у поля. Проверка MUST NOT блокировать и MUST NOT откатывать сохранение ни при каком исходе: значение уже записано, а
результат — только предупреждение. Результат проверки MUST быть описанием поля и MUST пропадать при правке значения. Принятый ключ MUST выделять поле и результат цветом успеха (зелёным); ключ, который источник не принял, и токен не того вида MUST выделять их цветом ошибки и помечать поле недействительным, как ошибку значения; идущая и несостоявшаяся проверка поле не выделяют.
Пустое значение MUST NOT проверяться. Запрос проверки MUST идти по той же сетевой политике, что и поиск GIF.

#### Scenario: Рабочий ключ
- **WHEN** пользователь вставляет действующий ключ KLIPY и уходит из поля
- **THEN** ключ сохранён, у поля сказано, что ключ работает, поле обведено зелёным

#### Scenario: Неверный ключ
- **WHEN** пользователь вставляет ключ GIPHY, на который GIPHY отвечает HTTP 401
- **THEN** ключ сохранён, у поля предупреждение, что GIPHY не принял ключ

#### Scenario: Нет сети
- **WHEN** пользователь сохраняет ключ KLIPY, а запрос проверки обрывается сетевой ошибкой
- **THEN** ключ сохранён, у поля предупреждение, что ключ не удалось проверить

#### Scenario: Токен не того вида
- **WHEN** пользователь вставляет в поле токена `abc`
- **THEN** токен сохранён, у поля предупреждение, что это не похоже на токен бота, запросов к Telegram нет
