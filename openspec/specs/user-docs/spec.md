# user-docs Specification

## Purpose
Дока пользователя amo stickers: сайт, по которому человек без опыта ставит расширение или userscript в свой браузер,
получает ключи GIF и токен бота и импортирует пак из Telegram; а README — вход, который ведёт на неё.

## Requirements

### Requirement: Сайт доки
Дока SHALL публиковаться сайтом на GitHub Pages по адресу `https://mcar2107.github.io/amo_msg_stickers/`, собранным из
исходников в Markdown в репозитории. Когда сайт публикуется — с релизом и ручным запуском, — задаёт требование
«Публикация доки» спеки `ci-cd`. У сайта MUST быть навигация по разделам, поиск по тексту и светлая и тёмная тема.

Дока SHALL быть на двух языках: русская — в корне сайта, английская — под `/en/` с тем же путём страницы
(`setup/gif-keys` → `/en/setup/gif-keys`). У каждой русской страницы MUST быть английская, и наоборот. В шапке MUST быть
переключатель языка, ведущий на ту же страницу на другом языке. Навигация, боковое меню, поиск и служебные подписи
сайта (оглавление, «назад» и «дальше», тема, страница «не найдено») MUST быть на языке страницы; поиск на странице одного
языка MUST NOT находить страницы другого. Английская дока MUST называть экраны, кнопки и поля amo stickers так, как их
показывает английский интерфейс. Скрины и видео у обоих языков MUST быть одни и те же файлы; подписи к ним — на языке
страницы. Сайт MUST NOT перенаправлять читателя по языку браузера: язык выбирает адрес.

#### Scenario: Правка доки
- **WHEN** в `master` попадает коммит, меняющий только исходники доки, без подъёма версии
- **THEN** сайт доки не меняется до релиза или ручной публикации, новый релиз не создаётся

#### Scenario: Битая ссылка
- **WHEN** страница доки ссылается на несуществующую страницу доки
- **THEN** сборка сайта падает с указанием ссылки

#### Scenario: Английская страница
- **WHEN** читатель открывает `https://mcar2107.github.io/amo_msg_stickers/en/setup/telegram`
- **THEN** страница импорта из Telegram, навигация и боковое меню — на английском, скрины — те же, что у русской
  страницы

#### Scenario: Переключение языка
- **WHEN** читатель на русской странице установки для Firefox выбирает English в переключателе языка
- **THEN** открывается английская страница установки для Firefox

#### Scenario: Адреса русских страниц
- **WHEN** читатель открывает адрес русской страницы, опубликованный до появления английской доки
- **THEN** открывается та же русская страница

#### Scenario: Поиск на английском
- **WHEN** читатель английской доки ищет «token»
- **THEN** в результатах только английские страницы

### Requirement: Разделы доки
Дока SHALL содержать разделы: главная (что это и выбор способа установки), установка, ключи GIF, импорт из Telegram,
обновление, частые вопросы, политика конфиденциальности. Шаги со сторонним интерфейсом (страница расширений, менеджер
userscript-ов, @BotFather, Telegram, панели KLIPY и GIPHY, Safari) и экраны amo stickers MUST сопровождаться скринами;
на главной MUST быть демо-видео отправки стикера. Личные данные на скринах (чужие имена, списки чатов, ключи, токены)
MUST быть скрыты. Место под скрин, которого ещё нет, MUST быть отмечено в исходниках и MUST NOT ломать сборку сайта.

#### Scenario: Скрина ещё нет
- **WHEN** место под скрин отмечено, а файла скрина в репозитории нет
- **THEN** сайт собирается, на странице нет битой картинки

#### Scenario: Демо на главной
- **WHEN** пользователь открывает главную доки
- **THEN** под описанием играет по кругу видео без звука: открытие панели стикеров и отправка стикера и GIF

### Requirement: Адреса страниц браузера
Адрес, который страница сайта открыть не может (`chrome://extensions`, `edge://extensions`, `browser://extensions` и
подобные), SHALL копироваться в буфер по клику, с отметкой «Скопировано» рядом — на английской странице «Copied». Без
доступа к буферу отметка MUST NOT появляться, адрес MUST оставаться видимым текстом, который можно выделить.

#### Scenario: Скопировать адрес страницы расширений
- **WHEN** пользователь нажимает `chrome://extensions` в таблице адресов на странице установки для Chromium
- **THEN** адрес в буфере обмена, рядом на полторы секунды появляется «Скопировано»

#### Scenario: Скопировать адрес на английской странице
- **WHEN** пользователь нажимает `edge://extensions` на английской странице установки для Chromium
- **THEN** адрес в буфере обмена, рядом на полторы секунды появляется «Copied»

### Requirement: Установка по окружениям
Раздел установки SHALL начинаться со страницы выбора окружения: браузер на Chromium (Chrome, Яндекс Браузер, Edge,
Opera, Brave, Vivaldi), Firefox, Safari, десктоп-приложение amo. Главная доки MUST вести на эту страницу. Для браузеров
на Chromium MUST быть три равноправных способа на вкладках: «Chrome Web Store» (рекомендуемый), «Архив», «Userscript».
Пока расширения нет в Chrome Web Store, вкладка MUST говорить об этом и вести к двум другим способам. Для Firefox MUST
описываться установка userscript, для Safari — userscript через приложение Userscripts. Раздел десктоп-приложения MUST
говорить, что способ пока недоступен.

- **Архив:** скачивание последней версии по прямой ссылке, установка распакованного расширения в режиме разработчика.
  Обновление — очистка папки расширения, распаковка новой версии в ту же папку и «Обновить» в списке расширений
  браузера. MUST быть предупреждение, что архив не обновляется сам, а распаковка в другую папку сбрасывает ключи и
  токен.
- **Userscript:** установка менеджера, установка скрипта в один клик по ссылке на последний релиз, разрешения,
  которые спросит менеджер. Основной менеджер — Tampermonkey; для Tampermonkey в Chrome MUST быть шаг включения
  пользовательских скриптов в настройках расширения. Violentmonkey и Safari (Userscripts) MUST быть помечены «без
  гарантий»: способ не проверяется. Для Safari MUST быть сказано, что настройки могут храниться в хранилище сайта amo,
  доступном его скриптам.

#### Scenario: Пользователь Яндекс Браузера
- **WHEN** пользователь нажимает «Установить» на главной доки и выбирает «Яндекс Браузер»
- **THEN** он попадает на страницу с вкладками «Chrome Web Store», «Архив», «Userscript»

#### Scenario: Менеджер без гарантий
- **WHEN** пользователь открывает установку для Safari или описание Violentmonkey
- **THEN** рядом со способом сказано, что он не проверяется, и предложен проверенный способ

#### Scenario: Установка userscript в один клик
- **WHEN** пользователь с установленным Tampermonkey нажимает в доке ссылку установки userscript
- **THEN** Tampermonkey открывает окно установки последней версии amo stickers

#### Scenario: Десктоп
- **WHEN** пользователь открывает раздел десктоп-приложения amo
- **THEN** на странице сказано, что способ пока недоступен, и нет инструкций, которые не сработают

### Requirement: Настройка ключей GIF
Раздел ключей GIF SHALL описывать получение ключа KLIPY и ключа GIPHY по шагам — от регистрации до вставки ключа в
«Настройки» amo stickers. KLIPY MUST идти первым и рекомендоваться за выбор контента. Шаг вставки MUST описывать
автосохранение: ключ сохраняется сам при уходе из поля, по Enter или «Назад», а у поля показывается результат
проверки, — и MUST NOT упоминать кнопку «Сохранить». Раздел MUST говорить, что у бесплатных ключей есть лимит
запросов — у GIPHY 100 запросов в час, у KLIPY — по данным Partner Panel на момент написания, — и что его тратят
поиск, подгрузка следующей страницы и тренды. Раздел MUST NOT обещать платные или боевые ключи.

#### Scenario: Упёрся в лимит
- **WHEN** пользователь читает частые вопросы о том, почему поиск GIF перестал работать
- **THEN** он находит объяснение лимита тестового ключа и что делать: подождать или завести ключ второго сервиса

#### Scenario: Вставка ключа
- **WHEN** пользователь проходит шаг вставки ключа KLIPY
- **THEN** дока говорит, что ключ сохранится сам, и что значит результат проверки у поля, без кнопки «Сохранить»

### Requirement: Импорт из Telegram
Раздел импорта SHALL начинаться с импорта без настройки: получение ссылки на пак в приложении Telegram и импорт по ней
на сегменте «Telegram» экрана «Добавить стикеры» — через встроенного бота, без токена в «Настройках». Раздел MUST
говорить, что инструкция на экране раскрыта только при первом показе и возвращается кнопкой «?» у поля ссылки.
Создание своего бота SHALL описываться отдельным необязательным разделом по шагам: создание бота в @BotFather,
копирование токена, вставка токена в «Настройки» (сохраняется сам, без кнопки «Сохранить»), — с объяснением, когда он
нужен: встроенный бот недоступен (ошибка об этом при импорте). Раздел своего бота MUST предупреждать, что токен —
секрет, даёт управление ботом и хранится только в браузере пользователя.

#### Scenario: Первый импорт
- **WHEN** пользователь без бота проходит раздел импорта по шагам
- **THEN** у него есть ссылка на пак, импорт стартует без токена в «Настройках»

#### Scenario: Встроенный бот недоступен
- **WHEN** при импорте показана ошибка, что встроенный бот недоступен, и пользователь открывает раздел импорта
- **THEN** он находит раздел своего бота и после его шагов импортирует пак со своим токеном

### Requirement: Политика конфиденциальности
Дока SHALL содержать политику конфиденциальности на отдельной странице с постоянным адресом:

- что хранится в браузере: ключи и свой токен бота, если он задан, — в хранилище расширения или менеджера userscript,
  а у userscript без хранилища менеджера — в хранилище сайта amo, доступном его скриптам; стикеры, недавние и
  выбранный режим попапа — в хранилище сайта amo;
- какие данные и куда уходят: поисковые запросы и ключ — в GIPHY или KLIPY; имя пака и токен — встроенного бота
  amo stickers или ваш, если он задан, — в Telegram; при загрузке GIF и файлов стикеров их серверы получают обычный
  запрос браузера с IP-адресом; отправленный стикер уходит в amo как обычное вложение сообщения;
- что разработчику не уходит ничего: запросы встроенного бота идут из браузера прямо в Telegram, а Bot API не
  показывает владельцу бота, какие паки запрашивались.

#### Scenario: Ссылка из карточки стора
- **WHEN** проверяющий стора открывает ссылку на политику конфиденциальности
- **THEN** страница открывается и перечисляет хранимые данные, сторонние сервисы и что разработчику ничего не передаётся

#### Scenario: Импорт встроенным ботом
- **WHEN** пользователь без своего токена читает политику о Telegram
- **THEN** сказано, что Telegram получает имя пака и токен встроенного бота, а разработчику запросы не видны

### Requirement: README как вход в доку
README репозитория SHALL начинаться с описания для пользователя: что это, как выглядит, что умеет, — и вести на доку
ссылкой «Установить». Рядом MUST быть ссылка на английскую доку для читателя без русского. Сборка, проверки и
устройство для разработчика MUST идти после и не заслонять путь установки.

#### Scenario: Посетитель репозитория
- **WHEN** посетитель открывает страницу репозитория на GitHub
- **THEN** на первом экране README — описание, демо и ссылка на установку, а не команды сборки

#### Scenario: Посетитель без русского
- **WHEN** посетитель открывает README и не читает по-русски
- **THEN** на первом экране есть ссылка на английскую инструкцию по установке

### Requirement: Порядок паков в доке
Частые вопросы доки SHALL объяснять, в каком порядке стоят паки в режиме «Стикеры»: «Недавние» и «Мои стикеры»
первыми, затем паки Telegram по последней отправке из раздела пака; новый пак — первым; отправка из «Недавних»
порядок не меняет; порядок обновляется при следующем открытии панели. Раздел MUST быть на русском и английском, а
ручной перестановки паков он MUST NOT обещать.

#### Scenario: Пак переехал
- **WHEN** пользователь видит, что пак в ленте сменил место, и ищет причину в доке
- **THEN** он находит в частых вопросах объяснение порядка по последней отправке

#### Scenario: Английская дока
- **WHEN** пользователь открывает частые вопросы на английском
- **THEN** там тот же вопрос о порядке паков с названиями экранов английского интерфейса
