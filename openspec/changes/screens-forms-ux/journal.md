Решения без заказчика, отступления от спеки, итоги аудитов и долг прогона change `screens-forms-ux`.

## 2026-10-06

Ключи GIPHY и KLIPY для 8.4 — переменные GIPHY_KEY и KLIPY_KEY в `.env` корня (значения в журнал, отчёты и коммиты не писать). Стенд — `dev/harness.html` (`python3 -m http.server 8777 -b 127.0.0.1`), `dev/amo.css` на месте; headless Chrome — по CLAUDE.local.md.

### G1 · Чистые модули ядра

Решения: признак инструкции хранится значением '1' (строго, как pickerMode); isBotTokenFormat снимает пробелы по краям; checkGifKey не бросает — любой сбой, кроме 401/403, даёт unavailable; KEY_REJECT_STATUSES локальна в gifs.ts (8.4 дополняет там); AddSegment (K1) заведён в usePickerView.types.ts в G1 — нужен сигнатуре importErrorTarget.
Аудит: ok с первого круга, мутации не понадобились.
Долг: проверка ключа KLIPY без media_filter — ответ тяжелее, на итог не влияет; KEY_REJECT_STATUSES не экспортирована.

### G2 · Словарь

Решения: ошибка неверной ссылки — имеющийся error.telegram.badLink (G5 берёт его); подпись поля — имеющийся add.custom.caption; «Токен хранится локально» вынесено из подсказок в settings.storedLocally; EN «Готово» → «Done» (перевод amo не сверен — вопрос в финал).
Отступление: settings.save и старые ключи (add.telegram.hint, add.custom.dropZone, settings.{giphy,klipy}.hint) не удалены — по K5 их удаляют G7 и G8; правлен tests/renderMessage.test.ts вслед за строкой подсказки.

Долг: G7 обязана вывести settings.storedLocally на экран; тест «подсказки токена не говорят о хранении» проверяет только RU; 10.2 убирает старые ключи.

### G3 · Каркас экрана и примитивы

1.2: headless Chrome 154 (CDP) — Enter в поле формы в закрытом shadow root шлёт submit с submitter = кнопка type="submit" form="<id>" вне формы; disabled — не шлёт. Основной вариант D3 в силе, запасной не нужен; Firefox не проверялся (поведение — стандарт HTML).
Решения: Button — union ButtonActionProps | ButtonSubmitProps; leave() для кнопок футера — ScreenContext + useScreenLeave (не render-prop); Screen рисует тело сам, ViewBody и SecretField удалены; Field — описание в порядке ошибка → результат → подсказка; общая высота футера — SCREEN_FOOTER_HEIGHT_PX = 48 inline-стилем (Tailwind не сканирует .ts); isTextField вынесен в общий модуль (вне файлов группы).
Аудит: ok с первого круга. Исполнитель сменён после 52 вызовов (эстафета на 4.4).
Долг: тип View в usePickerView.types.ts больше не используется — удалить в G4; AddView footer={null} до G4; useScreenLeave не переиспользует тип ScreenLeave.

### G4 · Сегменты «Добавить стикеры»

Решения: формы сегментов — SegmentForm (`<form role="tabpanel" hidden>`) в AddView, кнопки — TelegramImportFooter и CreateStickerFooter (уже лежат в каталогах G5/G6) с type="submit" form; раскладка полей во вложенном div (flex на форме перебил бы hidden); resolveAddSegment, DEFAULT_ADD_SEGMENT = 'telegram'; saveBlock({ hasFile, isConverting }): без файла — noFile даже при сборке; isDraftConverting: окно задержки подписи (500 мс) считается сборкой.
Решения координатора: окно задержки подписи → сборка — по букве custom-stickers «Сборка после правки подписи» (аудитор поднял question, спека это покрывает), отдано вторым critical. G5 разрешено править AddView.tsx (провод ошибки поля ссылки): волна 4 идёт последовательно в одном дереве; альтернатива — проп fieldError заранее в G4.
Аудит: 1 круг доработки — critical: isConverting не доходил до CreateStickerProps (K9); окно задержки подписи. Оба закрыты. Исполнитель сменён после 75 вызовов.
Долг: TelegramImport получает isActive, но читает его только G5; удержание попапа conversion не держится в окне задержки ввода (при фокусе в поле держится); провод openScreen и ARIA tabs проверен исполнителем на стенде, тестами — только resolveAddSegment.

### G7 · Настройки: автосохранение и проверка

8.4 (живые API): GIPHY — действующий 200, неверный 401; KLIPY — действующий 200, неверный HTTP 404 «The provided API key is invalid.». KEY_REJECT_STATUSES стал Record по источникам: KLIPY 401/403/404, GIPHY 401/403 (404 у GIPHY — сбой адреса, unavailable, отдельный тест). Спека «Проверка ключей и токена» называет только 401/403 — в правки артефактов.
Решения: чтение и запись настроек — одна очередь промисов в провайдере; saveSettings(patch): Promise<boolean>, не отклоняется; правки живут всё время монтирования экрана; change — одной подпиской на <form>; при размонтировании проверки нет; «хватит одного ключа» — describedBy обоих полей GIF; storedLocally над группами; gap-4 между группами, gap-1 внутри — буквально по D10.
Аудит: ok с первого круга. Исполнитель сменён после 61 вызова.
Вопросы к пользователю: (1) «Сохранено» после неверного ключа GIPHY через <250 мс перекрывается сырой ошибкой ленты GIF (useGifFeed, вне G7) — против picker-states «статус держится до следующего действия»; (2) 4 px из D10 применены и между полями группы — поля визуально сливаются.
Долг: settingsRef обновляется в useEffect — в окне ~кадр после записи уход из поля пишет то же значение повторно; «Готово» запускает проверку ключа, ответ которой отбрасывается при уходе экрана (тратит лимит), «Назад» не проверяет — выбрать одно или записать в D9; оркестровка useSettingsDraft (таймер, размонтирование) покрыта только стендом.

### G5 · Импорт из Telegram

Решения: ход импорта вынесен в чистый runPackImport (PickerProvider/runPackImport/, новый модуль вне списка файлов G5) с тестами; importPack() без аргумента, ссылка в провайдере; ошибка у поля снимает статус (clearStatus); ссылка без имени пака — всегда ошибка у поля; «?» — HintToggle absolute над строкой подписи (не в <label>); инструкция — свой <p id hidden> для aria-controls; useImportHint повторяет обёртку PAGE_STORAGE (та не экспортирована).
Решения координатора: G5 правит AddView.tsx (провод fieldError) — волна последовательная; удаление неиспользуемого add.telegram.hint из словарей поручено G5 координатором — аудитор поднял его critical по K5, снято решением (ключ нигде не используется, дерево общее), круга нет.
Стенд: неверная ссылка — ошибка у поля, 0 запросов; несуществующий пак со встроенным токеном — HTTP 400 у поля; уход во время импорта — прогресс и ссылка сохраняются; инструкция раскрыта при первом показе, свёрнута после «Назад» и перезагрузки; сбой localStorage — раскрыта всегда. Успешный импорт с очисткой ссылки на стенде не подтверждён (без менеджера скачивание файлов Telegram падает «Failed to fetch») — только тест.
Аудит: ok по сути, единственный critical снят решением координатора.
Вопрос к пользователю: «пак не найден» показывается сырым `HTTP 400 {…STICKERSET_INVALID}` (telegram.ts, вне change).
Долг: связка колбэков usePackImport покрыта только стендом; ошибка импорта при закрытом попапе с открытым экраном уходит к полю (видна после открытия).

### G6 · Свой стикер

Решения: «Выбрать файл» — свой нейтральный <button> в DropZone, не Button primary: кольцо фокуса на акцентной заливке не видно (скрин); зона — div с drag-обработчиками, диалог открывает только кнопка (D7); превью при previewUrl || isConverting, спиннер на шахматке min-h-16; add.custom.dropZone удалён по поручению координатора.
Стенд (Chrome 154, EN и RU): «No file chosen» нет в дереве доступности; Shift+Tab → «Choose file» с кольцом, Enter → input.click(), попап держится; drop принят, к amo не уходит; правка подписи → aria-busy + спиннер + «Building the sticker…»; Enter во время сборки не сохраняет.
Аудит: ok с первого круга.
Долг: CHOOSE_BUTTON_CLASS дублирует базу buttonVariants — вариант secondary у Button; у основных кнопок (футер «Сохранить», «Импорт») кольцо фокуса не видно на акцентной заливке (picker.css/Button) — в итоговый аудит; ~45 мс между концом задержки подписи/выбором файла и стартом сборки isConverting=false — спиннер мигает, причина пропадает на кадр (useStickerDraft); на стенде 127.0.0.1:8777 остались 2 тестовых стикера, PNG — local/g6/cat.png.
