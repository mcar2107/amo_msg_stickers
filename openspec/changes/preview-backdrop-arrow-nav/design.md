## Context

Предпросмотр один на панель (`PreviewProvider`), слой рисуется в отдельный shadow root (`PreviewLayer`) и контекста
панели не видит — состояние и действия приходят пропсами из `PreviewOverlay`. Состояние — `{ target, mode, source,
isLeaving }`: `source` — кнопка ячейки, от неё летит картинка, в неё возвращается и на неё встаёт фокус. Смену ячейки
при удержании слой уже переживает без новой анимации: вылет и уход зависят от `isShown` / `isLeaving`, а не от
`target`, фокус закреплённого — от `isPinned` / `isLeaving`.

Обе ленты виртуальные: в документе только окно — видимая область и запас на её высоту сверху и снизу. Раскладка
известна заранее: у стикеров — ряды (`stickerLayout`, `StickerRow.items`), у GIF — плитки с колонкой и `top`
(`splitColumns`). id есть у каждой ячейки стикера (`cellId(sectionId, key)`) и только у недавних GIF
(`gifCellId(key)`).

Подложка сейчас — `bg-white-0/90 backdrop-blur-sm dark:bg-gray-10/90` (4 px размытия, 90 % заливки).

## Goals / Non-Goals

**Goals:**
- Сосед ячейки ищется по данным раскладки, а не по DOM: порядок узлов в окне не совпадает с порядком ленты (окно
  точки перехода, абсолютное позиционирование).
- Новые GIF, подгруженные, пока предпросмотр открыт, сразу участвуют в навигации.

**Non-Goals:**
- Навигация в предпросмотре удержания и в превью черновика своего стикера.
- Переключение с анимацией (сдвиг картинки) — смена мгновенная, как при удержании.

## Decisions

**Навигатор от ленты через контекст.** Лента (`StickerFeed`, `MasonryGrid`) кладёт в контекст
`PreviewNavigationContext` функцию `navigate(source, direction) → { target, source } | null`. `useCellPreview` читает
её (вне ленты — `null`) и отдаёт в `openPinned(target, source, navigate)`; состояние закреплённого предпросмотра
хранит `navigate`. Провайдер получает `step(direction)`: у открытого закреплённого с навигатором зовёт его от текущего
`source` и ставит `{ ...current, target, source }`; `null` — край, состояние не меняется.
Альтернатива — регистрация навигатора активного режима в провайдере: пришлось бы следить за сменой режима и экрана и
отличать превью черновика. Навигатор в состоянии сам говорит, есть ли у этого предпросмотра лента.

**Навигатор стабилен и читает раскладку из ref.** Функция в контексте — `useCallback` без зависимостей поверх ref с
последней раскладкой, `urlOf` и `scrollRef`: в состоянии лежит навигатор, захваченный при открытии, а выдача GIF
подгружается и пока предпросмотр открыт.

**Позиция ячейки — по `source.id`.** Навигатор ищет текущую ячейку в раскладке по id кнопки, соседа — чистыми
функциями, затем берёт его кнопку `getElementById` в корне ленты. У GIF id получают все ячейки:
`gifCellId(sectionId, key)` — ключ GIF уникален только в разделе (та же GIF в недавних и выдаче), как у стикеров.
`useGifRemovalFocus` передаёт id раздела недавних.

**Чистые функции соседа** (с тестами):
- `stickerNeighbor(rows, id, direction)` — по рядам с ячейками (заголовки, подсказки и ряд из одной плитки
  пропускаются, плитки нет в `items`): влево/вправо — плоский порядок рядов, вверх/вниз — соседний ряд, колонка
  `min(column, length − 1)`.
- `masonryNeighbor(tiles, id, direction)` — только плитки `item`: влево/вправо — порядок выдачи, вверх/вниз —
  предыдущая/следующая плитка той же колонки (порядок плиток в колонке совпадает с ростом `top`).

**Кнопка соседа уже в документе.** Текущая ячейка видна (с неё открыто меню, и каждый шаг держит показанную видимой),
соседний ряд или плитка лежит в пределах высоты видимой области — в запасе окна. Если кнопки всё же нет, шаг — как на
краю: `null`.

**Прокрутка к показанной ячейке — по геометрии раскладки.** Новый `scrollTop` считает чистая
`revealScrollTop(top, height, scrollTop, viewport)` — минимальный сдвиг, чтобы ячейка была видна целиком; ставится
мгновенно (`scrollTop =`), без `scrollIntoView`: тот прокручивает и предков, вплоть до страницы amo. Окно ленты
пересчитывается по событию прокрутки, как при ручной прокрутке.

**Клавиши — в слое.** `handleContentKeyDown` переводит `ArrowLeft/Right/Up/Down` в направление (`previewDirection`,
`switch` по `event.key`), зовёт `onStep` и гасит действие по умолчанию — прокрутку страницы. Шаг не трогает фокус: он на
кнопке «Закрыть предпросмотр» или на слое.

**Объявление.** Имя диалога (`aria-label`) меняется вместе с `target`, но смену имени скринридеры не читают. Поэтому в
слое — live region `aria-live="polite"` (`sr-only`), который получает имя ячейки только после шага (`stepCount` в
состоянии): при открытии диалог объявляется своим именем, и второе объявление было бы лишним. Узел с именем
пересоздаётся по `key` от счётчика: у соседа с тем же именем текст не меняется, и без нового узла шаг не объявился бы.

**Подложка** — `bg-white-0/40 dark:bg-gray-10/40`, без `backdrop-blur` (решение заказчика): лёгкая пелена, сквозь
которую лента читается как есть; итог сверяется на стенде в обеих темах. Переход прозрачности и `[@starting-style]` не трогаются.

## Risks / Trade-offs

- [Картинка с прозрачностью на видимой ленте без размытия читается хуже] → принято заказчиком: пелена важнее
  отделения; проверка на стенде со стикером с прозрачным фоном в обеих темах.
- [Зажатая стрелка прокручивает ленту быстрее, чем окно перерисовывается] → сосед всегда в запасе окна (высота видимой
  области), а пропуск кнопки — безопасный край без смены.
- [Строка статуса лежит поверх низа ленты] → ячейка под ней «видна» по геометрии, но частично закрыта; приемлемо:
  возврат картинки идёт в её место, фокус встаёт на неё.
