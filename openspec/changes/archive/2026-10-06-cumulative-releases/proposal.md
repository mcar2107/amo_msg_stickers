## Why

Каждый PR, меняющий файлы продукта, обязан поднять версию, а мерж каждого такого PR выпускает релиз и отправляет его в
Chrome Web Store: 15 релизов за 10 дней, мелкие правки уходят по одной, и каждая — отдельная проверка стора и отдельное
обновление у пользователя. Нужны накопительные релизы: правки копятся в `master` и выходят пачкой, когда её решили
выпустить (issue #92).

## What Changes

- Проверка версии в PR больше не требует подъёма версии: PR с правками продукта мержится без подъёма и без релиза.
  Если PR версию меняет, она MUST быть не ниже версии в `master`.
- Релиз — PR, который поднимает версию. Его мерж, как и сейчас, выпускает тег, GitHub Release с заметками по всем PR
  со времени прошлого тега и отправку в стор. Срочный фикс поднимает версию в самом PR и выходит сразу.
- Мерж без подъёма версии — штатный случай: прогон в `master` отмечает, что релиз не выпускается, без предупреждения.
- **BREAKING** (для процесса, не для пользователя): версия записана только в `package.json`. `version` из
  `src/extension/manifest.json` и литерал `@version` в `build.mjs` удаляются — сборка подставляет версию
  `package.json` в собранный manifest и в заголовок userscript. Проверка совпадения трёх мест удаляется.
- Дока публикуется на GitHub Pages по выходу релиза и вручную, а не по каждому мержу в `master` с правками `docs/`:
  сайт не описывает ещё не выпущенное.
- Правила процесса — раздел «CI и релизы» в `CLAUDE.md`, `docs/README.md` и скилл `task-workflow` — описывают новый
  порядок: подъём версии уходит из шагов обычного PR, появляется PR релиза.

### Modified Capabilities

## Impact

- `build.mjs` — версия из `package.json` в manifest `dist/extension` и в `@version` userscript.
- `src/extension/manifest.json` — без `version`.
- `scripts/version.ts`, `scripts/check-version.mjs`, `tests/version.test.ts` — проверка формата версии и «не ниже
  базы» вместо совпадения трёх мест и обязательного роста.
- `.github/workflows/release.yml` — уведомление вместо предупреждения, вызов публикации доки после релиза.
- `.github/workflows/pages.yml` — запуск из релиза (`workflow_call`) и вручную вместо push в `master`.
- `CLAUDE.md`, `docs/README.md`, `.claude/skills/task-workflow/SKILL.md` — описание процесса.
- Пользователь расширения и userscript изменений не видит: версии и адреса обновления те же.
