## Why

Импорт пака из Telegram работает, только если пользователь сам заведёт бота в @BotFather и вставит его токен в
«Настройки» (issue #83). Для большинства пользователей это барьер: после установки импорт не работает. Бот нужен только
для `getStickerSet`, `getFile` и скачивания файлов стикеров и никому не пишет, поэтому токен своего бота можно встроить в
сборку: утечка из бандла грозит чужим расходом лимитов бота или `logOut`, то есть сломанным импортом до перевыпуска
токена, а не данными пользователей. Этот риск принят; прокси для Bot API (#42) отклонён — из российской сети Cloudflare
режется на первых 16 КБ ответа, а новый хост в правах отключил бы расширение при обновлении.

## What Changes

- Сборка подставляет токен встроенного бота из переменной окружения `TELEGRAM_BOT_TOKEN` в бандлы content script и
  userscript. Без переменной токена в сборке нет, и импорт ведёт себя как сейчас — просит свой токен. Значение не
  формата `<цифры>:<строка>` роняет сборку.
- CI: job `build` получает секрет репозитория `TELEGRAM_BOT_TOKEN`; релиз вызывает проверки с секретами и выкладывает тот
  же артефакт сборки. PR из форка секрета не получает — его сборка без токена. Токена нет в git.
- Импорт идёт по своему токену из «Настроек», а без него — по встроенному. Встроенный токен не показывается в
  «Настройках» и не пишется в хранилище: поле токена — только для своего.
- Подсказка у поля токена в «Настройках» при встроенном токене говорит, что свой токен необязателен и нужен, если
  встроенный бот недоступен; без встроенного — как сейчас.
- Отказ Bot API встроенному боту (HTTP 401 — токен отозван, HTTP 429 — лимит) показывается ошибкой «встроенный бот
  недоступен, укажите свой токен в настройках», а не сырым `HTTP <код>`.
- Дока на обоих языках: раздел импорта начинается с импорта без бота, создание своего бота — необязательный раздел;
  политика конфиденциальности — Telegram получает токен встроенного бота или вашего; главная и частые вопросы не
  требуют токена для импорта.
- Версия — минор, 0.17.1 → 0.18.0.

### Modified Capabilities

- `telegram-import`: импорт по своему токену или встроенному, ошибка «нет токена» — только без обоих, отказ
  встроенного бота с подсказкой задать свой, хранение токена — только своего.
- `runtime-hosts`: подсказка у поля токена зависит от наличия встроенного токена.
- `ci-cd`: сборка в CI и релиз несут встроенный токен из секрета, сборка без секрета — без него, неверный формат
  роняет сборку.
- `user-docs`: раздел импорта без обязательного бота, политика конфиденциальности о встроенном токене.

## Impact

- Сборка: `build.mjs` (`define` токена, проверка формата), чистая проверка формата в `scripts/`, `src/types.d.ts`
  (объявление константы), `vitest.config.ts` (значение константы в тестах).
- Ядро: модуль встроенного токена в `src/core/`, `src/core/sources/telegram.ts` (выбор токена, отказ встроенного бота),
  `src/core/net.ts` (статус из ошибки `httpError`), `SettingsView` (подсказка), словари `messages.ru.ts` /
  `messages.en.ts`.
- CI: `.github/workflows/ci.yml` (секрет в job `build`), `.github/workflows/release.yml` (явная передача секрета у вызова
  проверок). Нужен секрет репозитория `TELEGRAM_BOT_TOKEN` — его заводит владелец репозитория.
- Дока: `docs/content/setup/telegram.md`, `privacy.md`, `index.md`, `faq.md` и их пары в `docs/content/en/`.
- `CLAUDE.md`: сборка, CI и внешние данные. Версия — `package.json`, `manifest.json`, `@version` в `build.mjs`.
- Схема настроек и IndexedDB не меняются, миграций нет.
