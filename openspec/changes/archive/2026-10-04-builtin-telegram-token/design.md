## Context

Мотивация — `proposal.md`. Что есть сейчас:

- `importTelegramSet(host, token, input, onProgress)` (`src/core/sources/telegram.ts`) получает токен из
  `settings.telegramToken` (`usePackImport`) и без него бросает `error.telegram.noToken`. Запросы — `call` (Bot API через
  `host.fetchJson`) и скачивание файла `host.fetchBlob` по `${TG_API}/file/bot${token}/…`.
- Не-2xx ответ во всех окружениях превращается в `httpError(status, body)` из `core/net.ts` — `Error` с текстом
  `HTTP <код> <начало тела>`. Через границу service worker ошибка доходит текстом: `fetchResponse.ts` пересоздаёт
  только `LocalizedError`, остальное — `Error` с текстом SW как есть.
- Настройки — `DEFAULT_SETTINGS` (`core/host.ts`) поверх сохранённых; `SettingsView` правит черновик всех полей и
  сохраняет его целиком.
- `build.mjs` собирает четыре бандла из общего `common`; `.mjs` уже импортирует чистую логику из `scripts/*.ts`
  (`check-version.mjs` → `version.ts`), тесты гоняют её из `tests/`.
- `release.yml` вызывает `ci.yml` (`workflow_call`) и выкладывает артефакт `build` его прогона — отдельной сборки у
  релиза нет.

## Goals / Non-Goals

**Goals:**

- токен встроенного бота попадает только в бандл из секрета CI и нигде больше не появляется: ни в git, ни в
  настройках, ни в интерфейсе;
- одно место в ядре решает, каким токеном идёт импорт и как показывать отказ встроенного бота.

**Non-Goals:**

- прокси для Bot API, ротация токена без релиза, удалённый конфиг с токеном;
- доступность `api.telegram.org` из сети пользователя;
- встроенные ключи GIF (#42).

## Decisions

**1. Подстановка — `define` esbuild, а не виртуальный модуль.** `common.define` в `build.mjs` задаёт
`__TELEGRAM_BOT_TOKEN__` строкой JSON для всех бандлов; в бандл значение попадает только там, где на него есть ссылка
(content script и userscript через ядро). Объявление — `declare const __TELEGRAM_BOT_TOKEN__: string` в
`src/types.d.ts`. Читает константу один модуль ядра — `src/core/builtinToken.ts` (`BUILTIN_TELEGRAM_TOKEN`), остальной
код импортирует его: тесты подменяют модуль `vi.mock`, а `vitest.config.ts` задаёт `define` пустой строкой, чтобы
импорт без подмены не падал на `ReferenceError`. Виртуальный модуль по образцу `gif-worker:code` отвергнут: Vitest
плагинов сборки не знает, и модуль пришлось бы мокать в каждом тесте, который тянет `telegram.ts`.

**2. Проверка формата — чистая функция в `scripts/`.** `readTelegramToken(value: string | undefined): string` в
`scripts/telegramToken.ts`: пусто или `undefined` — `''`; значение обрезается от пробелов и переводов строки (секрет,
вставленный с концом строки); не `^\d+:[\w-]+$` — `Error` с текстом о формате, без самого значения. `build.mjs`
зовёт её на `process.env.TELEGRAM_BOT_TOKEN` до сборки и печатает одну строку «встроенный токен Telegram: есть / нет»
— без значения. Тест — `tests/telegramToken.test.ts`.

**3. Выбор токена — в `importTelegramSet`.** Сигнатура не меняется, второй аргумент — свой токен из настроек:
`token = ownToken || BUILTIN_TELEGRAM_TOKEN`, встроенный — когда своего нет, а встроенный есть. Ошибка `noToken` — только
без обоих. Альтернатива — выбор в `usePackImport` — отвергнута: правило отказа встроенного бота живёт рядом с запросами
к Bot API, и его проверяют тесты `telegram.test.ts`, а не хук.

**4. Отказ встроенного бота — по статусу из текста `httpError`.** В `core/net.ts` рядом с `httpError` появляется
`httpStatus(error): number | null` — разбор своего же формата `HTTP <код> …`: формат задаёт один модуль, и он одинаков в
SW, `gmNetwork` и `fetchNetwork`. На встроенном токене `call` и скачивание файла оборачиваются: статус 401 или 429 —
`LocalizedError('error.telegram.builtinUnavailable')`, остальное пробрасывается как есть (пак не найден — 400, сеть —
без статуса). Отказ на `getFile` или файле стикера останавливает цикл по стикерам: он касается всего пака, и следующие
запросы ушли бы с тем же отозванным токеном или в тот же лимит общего бота. Уже импортированные стикеры остаются, импорт
завершается той же ошибкой; при нуле импортированных пак откатывается, как при любом отказе. Класс `HttpError` со
статусом отвергнут: граница SW передаёт ошибку текстом, и пришлось бы менять протокол `fetchResponse.ts` ради одного
места. 403 не входит: Bot API отдаёт его, когда пользователь заблокировал бота, — к импорту не относится.

**5. Настройки не знают о встроенном токене.** `DEFAULT_SETTINGS.telegramToken` остаётся `''`: иначе встроенный токен
оказался бы в черновике `SettingsView`, в поле ввода и при «Сохранить» — в хранилище. `SettingsView` выбирает подсказку
по `BUILTIN_TELEGRAM_TOKEN`: есть — `settings.telegram.hintOptional` (свой токен необязателен, нужен, если встроенный бот
недоступен; ссылки на @BotFather и доку), нет — прежняя `settings.telegram.hint`. Подпись поля при встроенном токене —
`settings.telegram.labelOptional` («Свой токен Telegram-бота (необязательно)»). Строки — парой в `RU` и `EN`.

**6. CI.** В `ci.yml` у шага `pnpm build` job-а `build` — `env: TELEGRAM_BOT_TOKEN: ${{ secrets.TELEGRAM_BOT_TOKEN }}`.
`ci.yml` объявляет секрет в `workflow_call.secrets`, `release.yml` передаёт его явно: вызванный workflow секретов не
видит, и релиз собрался бы без токена. `secrets: inherit` отвергнут — он отдал бы проверкам все секреты репозитория,
а им нужен один. Незаданный секрет даёт пустую строку — сборка без токена, а не падение: так проходят PR из форка и
Dependabot. Сборка PR из своей ветки несёт токен в артефакте — токен в релизе всё равно публичен.

## Risks / Trade-offs

- [Токен достают из бандла и тратят лимиты или зовут `logOut`] → риск принят (issue #83); перевыпуск токена в
  @BotFather, новый секрет и патч-релиз; пользователь не ждёт релиза — ошибка отказа ведёт его к своему токену.
- [Лимиты Bot API на `getStickerSet` / `getFile` не опубликованы, общий бот может упереться в 429] → та же ошибка с
  подсказкой своего токена; пережимать импорт или ставить паузы не будем, пока 429 не видно.
- [Разбор статуса из текста ошибки зависит от формата `httpError`] → формат и разбор в одном модуле, тест на пару
  `httpError` → `httpStatus`.
- [Релиз выйдет без токена, если секрет не заведён] → поведение как сейчас, ничего не ломается; строка «встроенный
  токен: нет» в логе сборки показывает это.

## Migration Plan

1. Владелец репозитория создаёт бота в @BotFather (имя и описание — amo stickers), запрещает добавлять его в группы
   (`/setjoingroups` → Disable) и заводит секрет: `gh secret set TELEGRAM_BOT_TOKEN`.
2. Мерж PR — релиз 0.18.0 со встроенным токеном; без секрета релиз выходит без него.
3. Откат: удалить секрет или перевыпустить токен — следующий релиз без токена или с новым; данные пользователей и
   настройки не меняются.
