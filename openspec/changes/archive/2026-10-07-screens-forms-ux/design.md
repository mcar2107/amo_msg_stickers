## Context

Экран поверх режима — `Screen/` (кнопка «Назад» и анимация `useScreenMotion`) с содержимым `AddView/` или
`SettingsView/`; шапка — `ViewHeader/` + `ViewTitle/` (`span`, не заголовок), тело — `ViewBody/` с прокруткой, главная
кнопка лежит в конце тела. `StatusBar/` — постоянная live region `absolute bottom-0 z-20` в области над футером панели:
на экране она ложится поверх низа экрана. Экран размонтируется при закрытии (`screen === null`), а при закрытии
попапа остаётся смонтированным.

Формы: `TelegramImport/` (ссылка — локальный `useState` хука `useTelegramImport`, ход импорта — `usePackImport` в
провайдере, ошибки — `showError` в статус), `CreateSticker/` (`useStickerDraft`: файл, подпись с задержкой 500 мс,
конвертация, `save` → `scrollToSection('custom', 'instant')`, что закрывает экран), `SettingsView/` (`useSettingsDraft`:
правки поверх объекта `settings`, сбрасываются перечитыванием настроек на открытие пикера; `save` → `env.setSettings`
+ `refreshSettings` + статус «Сохранено»). Поля — `TextInput/`, кнопки — `Button/` (только `onClick`, без `type`).
Решения пользователя по открытым вопросам issue #91 — в proposal.md.

## Goals / Non-Goals

**Goals:**
- Общий каркас экрана (заголовок, тело, футер, фокус) для обоих экранов — без дублирования в представлениях.
- Отправка форм Enter-ом штатным механизмом браузера, а не своими обработчиками `keydown`.
- Автосохранение настроек, которое не теряет ввод ни на одном пути ухода с экрана.

**Non-Goals:**
- Обрыв сетевого запроса, который уже в полёте, при отмене импорта: контракт `Host` без `AbortSignal`, а в
  расширении запрос идёт в service worker-е через сообщение.
- Обложка пака в карточке: картинка набора — ещё `getFile`, скачивание и отрисовка до импорта.
- Смена схемы хранения настроек и формата `Settings`.
- Проверка токена Telegram запросом к Bot API (решение пользователя: только формат).
- Вынос общей проверки формата токена из `scripts/telegramToken.ts` в ядро — у сборки и ядра разные границы импорта.

## Decisions

### D1. Каркас экрана — `Screen` с заголовком и футером

`Screen` получает `title` и `footer` и рисует: одну строку с `h2` с `id` слева и «Назад» справа (длинный заголовок
обрезается многоточием, «Назад» не сжимается), слот тела и футер экрана вне прокрутки
фиксированной высоты (класс-константа рядом с `Screen`). Корень — `<section aria-labelledby>` на `h2`.
`ViewHeader`/`ViewTitle` в экранах больше не нужны (в режимах остаются).

Фокус при монтировании ставится в первое текстовое поле формы экрана (решение пользователя): `Screen` ищет в теле
первый `input` текстового типа без `disabled` среди видимых (у «Добавить стикеры» неактивная панель сегмента `hidden`)
и фокусирует его. Только когда появление экрана проигрывается — экран открыт внутри открытого попапа (тот же признак,
что у `useScreenMotion`): при повторном открытии попапа на экране фокус не переносится. Смена сегмента фокус не
трогает — он остаётся на вкладке, как у паттерна ARIA tabs. Поле подписи «Свой стикер» стоит ниже зоны загрузки, но
фокус идёт в него, а не на кнопку «Выбрать файл»: Enter по привычке не открывает диалог файла, а подпись можно ввести
до выбора. Фокус в поле ставит причину удержания `field` — экран открыт кликом, и удержание попапа здесь ожидаемо.

### D2. Строка статуса над футером экрана

`StatusBar` получает вариант `isRaised` (экран открыт) и сдвигается на высоту футера экрана той же константой. Live
region остаётся одним узлом — переносить её внутрь экрана нельзя: область, появившаяся вместе с текстом, не
объявляется. Альтернатива — замер футера `ResizeObserver` — отвергнута: высота футера постоянная.

### D3. Формы — `<form>` и кнопка с атрибутом `form`

Тело сегмента или экрана — `<form id onSubmit>` с `preventDefault`, кнопка футера — `type="submit" form={id}`.
Неявная отправка Enter-ом работает и для кнопки вне формы, связанной атрибутом `form`, а недоступная кнопка по
умолчанию блокирует неявную отправку — так спека «Enter, включая недоступность» выполняется браузером. `Button`
получает необязательные `type` и `form`, `onClick` становится необязательным для `submit`. Id внутри закрытого
shadow root уникальны в своём дереве. Альтернатива — `onKeyDown` Enter на каждом поле — отвергнута: дублирует
правила доступности кнопки.

У каждого поля — `<label htmlFor>`; подсказка, ошибка и результат проверки — узлы с id в `aria-describedby` поля
(`TextInput.describedBy` принимает несколько id через пробел), ошибка значения — ещё и `aria-invalid`. Общий
компонент поля `Field/` (подпись, поле, описание) заменяет `SecretField` и разметку полей «Добавить стикеры»;
скрытие значения и кнопка показа — значок глаза внутри поля справа с именем «Показать» / «Скрыть» — вариант `Field`.

### D4. Сегменты «Добавить стикеры»

`usePickerView` получает `addSegment: 'telegram' | 'custom'` и `openScreen(screen, segment?)`: «+» вызывает без
сегмента (остаётся последний выбранный, по умолчанию `telegram`), плитка — с `custom`. Выбор сегмента живёт в
состоянии вида — переживает закрытие экрана и попапа до перезагрузки страницы, в `localStorage` не пишется.

Переключатель — ARIA tabs с `moveTabFocus/`, как у режимов. Обе панели смонтированы, неактивная `hidden`: ссылка и
черновик стикера переживают смену сегмента. Хуки `useTelegramImport` и `useStickerDraft` вызывает `AddView` — футер
зависит от активного сегмента и состояния его формы — и раздаёт состояние панелям пропсами.

### D5. Импорт: ссылка и ошибка поля в провайдере

Ссылка и ошибка поля переезжают из локального состояния хука в `usePackImport`: ссылка переживает размонтирование
экрана, а ошибка импорта, который закончился позже, находит поле. `importPack` сначала разбирает ссылку
(`parseSetName`): без имени — ошибка поля, без запроса. На ошибке импорта: если в момент завершения открыт экран
`add` на сегменте `telegram` — ошибка поля, иначе — `showError` в статус (решение — чистая функция рядом с
`finishImport`, с тестом). Успех очищает ссылку и ошибку. Правка ссылки снимает ошибку поля.

### D6. Инструкция импорта (#89)

Модуль `core/importHint.ts` по образцу `pickerMode.ts`: `readHintSeen(storage)` / `writeHintSeen(storage)`, ключ
`amo-stickers:import-hint-seen`, сбой чтения — «не видел», сбой записи молчит. `AddView` при монтировании читает
признак один раз: не видел — инструкция раскрыта; при первом показе панели `telegram` признак пишется. Закрытие и
повторное открытие экрана монтирует `AddView` заново — инструкция уже свёрнута. Кнопка «?» у подписи поля ссылки
переключает раскрытие (`aria-expanded`, `aria-controls`), раскрытая инструкция входит в `aria-describedby` поля.
«Первый показ» — показ сегмента, а не первый успешный импорт: так требует критерий готовности #89.

### D7. Свой стикер: зона загрузки и состояние сборки

Нативное поле файла скрыто, диалог открывает кнопка «Выбрать файл» / «Заменить файл» (`input.click()`), удержание
`fileDialog` ставится по её нажатию — как сейчас по клику на поле. Так имя элемента в дереве доступности — из словаря,
без строки браузера «Файл не выбран». Перетаскивание остаётся на контейнере зоны. Кольцо фокуса — у кнопки по
`:focus-visible`, как у остальных кнопок. Без файла в зоне — иконка (svg в компоненте), текст о перетаскивании и
«Выбрать файл»; после выбора превью (`DraftPreview/`, слот `preview` зоны) занимает всю зону, а имя файла и маленькая
«Заменить файл» лежат плашками поверх него. Высота зоны одна в обоих видах, своего заголовка у панели нет (её называет вкладка): сегмент помещается в
панель 350×400 без прокрутки. Превью — кнопка «Увеличить стикер» со значком лупы: удержание и нажатие открывают
предпросмотр через `useCellPreview`, как у ячейки ленты (нажатие — закреплённый: отправки у черновика нет).

`useStickerDraft` отдаёт `isConverting` и причину недоступности сохранения (`'noFile' | 'converting' | null`). Пока
идёт сборка — `CellSpinner` поверх превью (или на шахматке, если картинки ещё нет) и `aria-busy`; причина — текст в
футере слева от кнопки, по левому краю и до двух строк: кнопка сохранения длинная, и в одну строку фраза не
помещается. Когда пояснять нечего, в том же слоте — размер и вес готового стикера (`draftSize`); в строку статуса
сборка пишет только ошибку. Сброс после сохранения уже обеспечен размонтированием экрана — меняется только то, что
черновик теперь живёт в `AddView`, которое тоже размонтируется.

### D8. Автосохранение настроек

Запись — через новый метод провайдера `saveSettings(next)`: `env.setSettings` + обновление `settings` без статуса
при удаче (принято ли значение, говорит проверка у поля; ошибка записи — в статус), последовательно в одной цепочке промисов; `refreshSettings` ждёт идущую запись — иначе перечитывание на
открытие попапа могло бы прочитать хранилище до записи и сбросить правки.

`useSettingsDraft` пишет изменённые поля: по `input` с задержкой 600 мс и сразу по уходу фокуса (`change`), Enter
(отправка формы), «Назад», переключению режима и закрытию экрана — эффект размонтирования делает
немедленную запись, если есть несохранённое. Закрытие попапа экран не размонтирует, но задержка ввода в
смонтированном экране всё равно срабатывает, а перечитывание ждёт запись (выше). Пишется только то, что отличается от
сохранённого: повторный уход из поля без правки не пишет.

Альтернатива — запись только по уходу фокуса — отвергнута: Escape закрывает попап без `blur` поля, и ввод не
записался бы до следующего открытия, когда перечитывание его сбросит.

Кнопки «Готово» и футера у «Настроек» нет: главного действия у экрана нет, а «Назад» уже записывает несохранённое.
`Screen.footer` необязателен; строка статуса поднимается над футером только у экрана с футером.

### D9. Проверка ключей и токена

`checkGifKey(host, provider, key)` в `sources/gifs.ts` — один запрос трендов с `limit=1` (GIPHY `gifs/trending`,
KLIPY `featured`) по той же сетевой политике; ответ формы выдачи — `ok`; `httpStatus(error)` 401 или 403 (у KLIPY ещё и 404 — им он отвечает на неверный ключ) — `rejected`;
остальное — `unavailable`. `isBotTokenFormat(token)` в `sources/telegram.ts` — `^\d+:[\w-]+$`. Обе — чистые, с
тестами.

Проверка запускается не на каждую запись с задержкой, а на «фиксации» значения — уход фокуса, Enter, «Назад»,
размонтирование: иначе каждая пауза при вводе тратила бы лимит GIPHY (100 запросов в час). Ключ
проверяется, только если отличается от последнего проверенного. Результат — состояние поля в черновике
(`checking | ok | rejected | unavailable | badFormat`), правка поля его снимает, устаревший ответ (значение уже
другое) отбрасывается по номеру запроса. Результат проверки после размонтирования экрана не показывается.

### D10. Иерархия и строки

Заголовок экрана — на ступень крупнее текущего `font-semibold` строки, группы `h3` — `text-xsm font-semibold`,
подписи — `text-xs`; отступ между группами — 16 px, внутри группы — 4 px; шрифт полей обоих экранов — `text-xsm`.
Конкретные классы — токены `tailwind.config.ts`, без новых.

Новые ключи словаря (`ru` эталон, `en` перевод): подписи полей («Ссылка на пак», «Подпись»), сегменты,
«Выбрать файл» / «Заменить файл», текст зоны, причины недоступности, кнопка «?», «Показать» / «Скрыть», группы «GIF» /
«Telegram», «хватит одного ключа», «хранится только в этом браузере», результаты проверки, ошибка неверной ссылки.
`settings.save` удаляется; ссылки на доку — «Инструкция» / «Instructions» с `whitespace-nowrap`.

### D11. Карточка пака (превью до и во время импорта)

`sources/telegram.ts` делится на два шага: `resolveTelegramSet(host, ownToken, name)` — `getStickerSet` с гардом
`isTgStickerSet`, тем же выбором токена и `guardBuiltin`, что у импорта; `importTelegramSet(host, ownToken, set,
onProgress, signal)` импортирует уже полученный набор. Разбор ссылки и проверка токена остаются до первого запроса.

Превью живёт в `usePackImport` рядом со ссылкой — переживает закрытие экрана. Запрос — по смене имени пака
(`parseSetName(link)`), а не текста: имя то же — запроса нет, ссылка без имени — превью снимается. Пауза 300 мс после
последней правки: вставка показывает карточку почти сразу, ввод руками не шлёт запрос на каждую букву. Ответ по
устаревшему имени отбрасывается по номеру запроса, как проверка ключа в D9. Нет ни своего, ни встроенного токена —
запроса нет.

Кэш — `Map<имя, Promise<набор>>` в `useRef` провайдера до перезагрузки страницы. Импорт берёт промис из кэша, а не
делает свой запрос: запущенный до ответа превью импорт ждёт тот же запрос, и `getStickerSet` уходит один раз на имя.
Отклонённый промис из кэша удаляется — повтор после сбоя сети делает новый запрос. Кэш и номер запроса — чистый модуль
рядом с провайдером (`packPreview/`), с тестом.

Исход превью — чистая функция `previewOutcome(error)`: HTTP 400 от `getStickerSet` (`httpStatus` из текста ошибки или
ответ `ok: false`) — «пак не найден»: текст ошибки, который показал бы импорт, встаёт к полю ссылки, «Импорт»
недоступна (как с пустым полем); остальное — 401 и 429 встроенного бота, сеть, битый ответ — превью снимается без
тона и ошибки, импорт не блокируется: он покажет свою ошибку сам. Правка ссылки снимает ошибку поля, как в D5.

Пак уже в библиотеке — в карточке второй строкой «Уже в библиотеке — импорт обновит пак». Признак считается при
показе по списку паков провайдера (`tg:<имя>`), а не запоминается с ответом: ответ лежит в кэше, пока имя то же, а
библиотека за это время меняется — импорт, частичный пак после ошибки, удаление пака.

Снимок импорта: на старте импорта `usePackImport` запоминает `{ title, total }` (из набора, а до его ответа — из
первого `onProgress`), и карточка показывает снимок, пока импорт идёт, а превью — когда нет: правка поля во время
импорта карточку не меняет.

Компонент `TelegramImport/PackCard/` заменяет `ImportProgress/`: строка — название (`truncate`) и справа
«Стикеров: N» (`tabular-nums`; строка без склонения — без `Intl.PluralRules`), во время импорта на месте числа «N/M»,
под строкой — полоса `role="progressbar"` с `aria-valuetext` (как была у `ImportProgress`). Загрузка — скелетон строки
с `aria-busy` и текстом «Загрузка пака…» для скринридера. id карточки входит в `aria-describedby` поля ссылки вместе с
раскрытой инструкцией: скринридер читает «Котики, стикеров: 45» с полем. Появление — `[@starting-style]:opacity-0` с
переходом под `motion-safe:`. Название пака — данные пользователя, не переводится.

Альтернатива — текст результата под полем (как проверка ключа, D9) — отвергнута: во время импорта он и полоса
прогресса были бы двумя блоками об одном паке.

### D12. Отмена импорта (#43)

Кнопка: `TelegramImportFooter` во время импорта рендерит тот же `Button` в том же месте без `key` — Preact обновляет
узел на месте, и фокус с «Импорт» остаётся на «Отменить» и возвращается обратно. «Отменить» — вариант `secondary`,
`type="button"`: Enter в поле ссылки её не нажимает. Форму с одним полем Enter отправляет и без кнопки `submit`,
поэтому импорт во время импорта не перезапускается проверкой недоступности «Импорт» в обработчике отправки формы. Клик с
`event.detail > 1` игнорируется: второй клик двойного клика по «Импорт» попал бы в «Отменить» и оборвал только что
начатый импорт; клик с клавиатуры даёт `detail === 0`. `Button` передаёт событие клика в `onClick`.

Отдельной «×» в карточке нет: два способа сделать одно, и маленькая цель рядом с полосой. Ушедший с экрана видит ход в
строке статуса, отменить — вернувшись на сегмент.

Механизм — `AbortController` в `usePackImport`, его `signal` — в `importTelegramSet` и `toStickerGif(blob, kind,
{ signal })`. Проверка `signal.throwIfAborted()` — перед `getFile`, `fetchBlob`, конвертацией и записью стикера, а в
конвертации — перед каждым кадром прохода (`writeFrames`) и перед каждым проходом лестницы (`encodeLadder`). Проход
закрывает приёмник кадров в `finally` — Worker кодирования останавливается, фолбэк на главном потоке перестаёт
получать кадры; источник кадров освобождается так же. Сетевой запрос в полёте не обрывается (Non-Goals), его ответ
отбрасывается проверкой после `await`, новых запросов нет.

Откат: до записи пака импорт запоминает прежнюю запись (`previous`, как сейчас) и id стикеров пака (`listStickers`
из `db.ts`). Отмена: пака не было — `deletePack` (пак и все его стикеры); был — прежняя запись `putPack(previous)` и
удаление стикеров пака, которых не было в снимке. Стикеры, перезаписанные повтором, — те же файлы Telegram по тому же
`file_unique_id`. Отмена — исключение `signal.reason` (`AbortError`), и `importTelegramSet` откатывает до броска.

`runPackImport` различает отмену (`signal.aborted`) и ошибку: исход `onCancel` — `refreshPacks`, статус «Импорт
отменён» через `showStatus`, а не `showError`, ссылка, карточка и ошибка поля не трогаются, лента не прокручивается.
`onFinish` снимает ход импорта, как сейчас, — с ним уходит причина удержания попапа `import`, и «Импорт» снова
доступна.

## Risks / Trade-offs

- [KLIPY на неверный ключ может отвечать не 401/403] → проверить на живом ключе при реализации; иной статус попадёт в
  «не удалось проверить», что не ломает сохранение. Список статусов отказа — константа рядом с `checkGifKey`.
- [Проверка тратит запрос лимита] → только на фиксации и только для изменённого ключа.
- [Неявная отправка формы с кнопкой вне `<form>` в shadow DOM] → проверить на стенде в Chrome первым шагом реализации;
  запасной вариант — кнопка футера внутри `<form>`, футер внутри формы.
- [Автосохранение пишет промежуточные значения при медленном вводе] → записи последовательны, последняя побеждает;
  проверка идёт только по зафиксированному значению.
- [Скрины доки устаревают] → `img/setup/telegram-import.png` переснимается на стенде; новые скрины, которых нет, —
  комментарием-заготовкой.

- [Запрос превью тратит лимит встроенного бота] → один `getStickerSet` на имя: кэш, и импорт берёт тот же запрос —
  итог по лимиту тот же, что без превью.
- [Скринридер может не объявить новое имя кнопки в фокусе] → проверить в VoiceOver на стенде; итог «Импорт отменён»
  объявляет строка статуса.
- [Отмена между записью стикера и проверкой] → откат идёт по снимку id до старта, а не по счётчику: записанный в
  момент отмены стикер тоже удаляется.

## Migration Plan

Хранилище настроек и формат не меняются. Новый ключ `localStorage` страницы `amo-stickers:import-hint-seen` создаётся
при первом показе сегмента. Откат — revert PR; оставшийся ключ `localStorage` ничему не мешает.
