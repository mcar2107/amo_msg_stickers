## ADDED Requirements

### Requirement: Проверка ответов Bot API
Система MUST проверять форму ответов Telegram перед использованием. Ответ `getStickerSet` без имени пака (латиница, цифры, подчёркивание), названия или списка стикеров MUST прерывать импорт с ошибкой, и пак MUST NOT добавляться в библиотеку. Путь файла из `getFile` MUST соответствовать `^(?!.*\.\.)[\w-][\w./-]{0,199}$`, иначе стикер MUST считаться упавшим без запроса файла. Файл стикера MUST скачиваться с лимитом 5 МБ (`runtime-hosts`, «Лимит размера загрузки»). Если не импортирован ни один стикер, импорт MUST завершаться ошибкой: новый пак MUST NOT оставаться в библиотеке, а ранее импортированный пак с тем же именем MUST остаться как был.

#### Scenario: Выход за пределы каталога файлов
- **WHEN** `getFile` возвращает `file_path` вида `../../bot<token>/sendMessage`
- **THEN** файл не запрашивается, стикер считается упавшим, импорт остальных продолжается

#### Scenario: Битый ответ getStickerSet
- **WHEN** `getStickerSet` возвращает `ok: true` без списка `stickers`
- **THEN** показана ошибка «Telegram: неожиданный ответ», пак в библиотеку не добавлен

#### Scenario: Битый стикер в паке
- **WHEN** у одного стикера из 30 нет `file_unique_id`
- **THEN** импорт доходит до 30/30, в паке 29 стикеров

#### Scenario: Ни одного пригодного стикера
- **WHEN** все стикеры пака упали при импорте
- **THEN** показана ошибка «Telegram: в паке нет пригодных стикеров», новый пак не добавлен, ранее импортированный пак остаётся как был
