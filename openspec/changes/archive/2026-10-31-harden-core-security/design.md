Мотивация — в `proposal.md`. Что есть в коде сейчас:

- `src/extension/background.ts:55-57` — `handleFetch` делает `fetch(url)` для любого `url` из сообщения; слушатель на `:86` игнорирует `_sender`.
- `src/extension/content.ts:20-26` и `src/userscript/index.ts:33-39` — `fetchJson<T>` возвращает `json as T`. Контракт в `src/core/host.types.ts:16-20` прямо перекладывает проверку на вызывающую сторону, но ни `gifs.ts`, ни `telegram.ts` её не делают: например, `images.original!` в `gifs.ts:57-58`.

- `src/core/convert.ts:444-446` — `new Response(blob.stream().pipeThrough(new DecompressionStream('gzip'))).json()` распаковывает всё без предела: `.tgs` в 50 КБ может развернуться в гигабайты.
- `src/core/app.ts:52-54` — `new Blob([blob], { type: 'image/gif' })` для ответа любого содержимого и размера.
- `src/extension/manifest.json:19-20` и `build.mjs:10` — `localhost:3000` / `127.0.0.1:3000` в боевой сборке.

Ограничения: UI (`src/core/ui/**`) сейчас переписывается на Preact, его не трогаем; обе цели сборки должны работать; новых зависимостей не заводим без нужды.

## Goals / Non-Goals

**Goals:**
- Одна сетевая политика в ядре, которую применяют оба `Host`.
- Все внешние данные проверяются на границе: ответы API — type-гардами, бинарные файлы — лимитом размера и проверкой формата.
- Каждая защита покрыта юнит-тестом.

**Non-Goals:**
- Проверка формата токена бота: это ввод самого пользователя в его же запрос, а неверный токен уже даёт понятную ошибку Telegram (требование «Импорт через Bot API»).
- Параллельное скачивание, повтор при 429 и отмена импорта — это PR 4.
- Переход KLIPY на нативный API — PR 5; здесь проверяется текущий формат Tenor v2.
- Ограничение размера своих файлов на вкладке «Добавить»: их выбирает сам пользователь, а видео и картинки декодирует браузер.

## Decisions

### S1. Политика адресов — модуль ядра `core/net.ts`
`isAllowedUrl(url)` принимает только `https:` с хостом `api.telegram.org` (точно, без поддоменов: у Bot API один хост), `giphy.com` или `klipy.com` со всеми их поддоменами (медиа раздают CDN). Хост сравнивается по `new URL(url).hostname`, а не регуляркой по строке: так отсекаются `giphy.com.evil.example`, `evilgiphy.com` и `https://api.telegram.org@evil.example/`. Список совпадает с `host_permissions` в manifest.
- **Почему в ядре, а не только в service worker:** userscript иначе вёл бы себя по-другому. Скачал бы ссылку, которую подсунул ответ API, с IP и `Referer` пользователя amo.
- **Альтернатива: только `host_permissions`.** Они не запрещают SW `fetch` к другим хостам, а только подчиняют такой запрос CORS: сам запрос всё равно уходит.

### S2. Service worker проверяет отправителя и итоговый адрес
Слушатель отвечает, только если `sender.id === chrome.runtime.id` и есть `sender.tab`, то есть сообщение пришло от content script этого расширения. После `fetch` та же политика проверяет `res.url`: редирект на чужой хост становится ошибкой.
- **Честно о пользе:** без `externally_connectable` в `onMessage` и так приходят только свои контексты. Проверка отправителя стоит две строки и страхует от будущих страниц расширения и изменений manifest.
- **Альтернатива: `redirect: 'error'`.** Не проверено, отдают ли CDN GIPHY и KLIPY файлы через редирект. Проверка итогового адреса безопаснее и ничего не ломает.

### S3. `Host.fetchJson` возвращает `unknown`, форму проверяют гарды источников
Сигнатура становится `fetchJson(url): Promise<unknown>`, `as T` в обоих `Host` исчезают. Гарды через `in` лежат рядом с типами, как `isLottieJson` в `convert.types.ts`: `isGiphyResponse`, `isTenorResponse`, `isTgResponse`, `isTgStickerSet`, `isTgFile`.
- Ответ не той формы целиком — ошибка с понятным текстом («GIPHY: неожиданный ответ»).
- Элемент выдачи без пригодного рендишна или со ссылкой вне политики S1 отбрасывается, остальные показываются. Это заменяет `images.original!` и `formats.gif!`.
- **Почему `unknown`, а не гард внутри `Host`:** компилятор не даст новому источнику использовать ответ без проверки. Правило становится проверкой типов, а не текстом в jsdoc.
- **Альтернатива: `valibot`.** Хорошо читается, и в референсе он есть. Но форм всего пять, ручные гарды в стиле проекта короче зависимости, а бандл не растёт.

### S4. `Host.fetchBlob(url, maxBytes)`: лимит обязателен, тело читается потоком
Сначала проверяется `Content-Length`, затем `readLimited(stream, maxBytes)` из `core/net.ts` читает тело. При превышении поток отменяется (`reader.cancel()`) и возникает ошибка «Файл больше N МБ». В расширении это происходит в SW, до base64 и до передачи в content script. `FetchRequest` получает поле `maxBytes`. Параметр обязательный, чтобы каждый вызов явно выбирал свой лимит.

Лимиты:

| Где | Лимит | Почему |
|---|---|---|
| GIF из поиска (`app.ts`) | 8 МБ | спека ждёт вариант около 2 МБ (downsized GIPHY), но KLIPY размер `gif` не гарантирует; 8 МБ в base64 — около 11 МБ сообщения, это приемлемо |
| Файл стикера Telegram | 5 МБ | у Telegram статичные стикеры до 512 КБ, `.tgs` до 64 КБ, видео до 256 КБ; запас на изменения лимитов |
| Распакованный `.tgs` | 8 МБ | Lottie стикеров — сотни КБ JSON |

### S5. Telegram: проверка пути, имени пака и каждого стикера
- `isTgFile` требует `file_path` по `^(?!.*\.\.)[\w-][\w./-]{0,199}$`. Регулярка из референса запрещает `..`, ведущие `/` и `.`, а также `?`, `#` и `%`.
- `isTgStickerSet` требует `name` по `SET_NAME_RE`: имя уходит в id пака `tg:<name>`.
- Каждый стикер проверяется внутри уже существующего `try` цикла импорта. Битый стикер считается упавшим, импорт идёт дальше — требование «Прогресс и частичные сбои» сохраняется.
- `file_unique_id` проверяется по `^[\w-]{1,64}$`: он уходит в id стикера.

### S6. `.tgs`: модуль `core/tgs.ts` с `readTgs(blob)`
Распаковка — `DecompressionStream('gzip')` + `readLimited` (8 МБ), затем `JSON.parse` и `isLottieJson`. Гард расширяется: `0 < w, h ≤ 4096`, числа `ip` и `op` с `op > ip`, массив `layers`, `fr` — по-прежнему необязательный. Отсутствие `fr` — осознанное решение автора (`DEFAULT_LOTTIE_FPS`), его сохраняем, а при наличии проверяем `0 < fr ≤ 120`.
- **Почему отдельный модуль:** его можно тестировать без canvas и Lottie.

### S7. GIF перед отправкой: модуль `core/gif.ts` с `inspectGif(bytes)`
Порт из референса: проверяет сигнатуру `GIF87a`/`GIF89a`, ненулевые размеры и проходит блоки до trailer. Возвращает `{ width, height, frames }` или `null`, если нет ни одного целого кадра. Отсутствие trailer допускается: браузеры такие файлы показывают. В `app.ts` `null` превращается в `SendError('Файл не похож на GIF')`: этот тип ошибки UI уже показывает.
- Свои стикеры из IndexedDB не проверяются: их сделал `encodeGif`.

### S8. Dev-адреса — только в `pnpm watch`
В `src/extension/manifest.json` остаются только `https://*.amo.tm/*`. `build.mjs` читает manifest и в режиме `--watch` добавляет в `content_scripts[0].matches` адреса `http://localhost:3000/*` и `http://127.0.0.1:3000/*`, а в заголовок userscript — те же адреса строками `@match`. Затем пишет результат в `dist/extension/manifest.json` вместо `cpSync`.
- **Почему watch:** это уже dev-режим проекта (inline-sourcemap, без minify). Отдельный флаг `--dev` дал бы третью комбинацию, которую никто не запускает.
- **Альтернатива: `manifest.dev.json`.** Два почти одинаковых файла расходятся при правках.

## Risks / Trade-offs

- **[CDN KLIPY или GIPHY на другом домене]** → политика S1 отбросит такие элементы выдачи, и источник покажется пустым. Проверяется в 6.3 с реальными ключами; тогда домен добавляется в политику и в `host_permissions` одновременно.
- **[Лимит 8 МБ отсечёт тяжёлый GIF KLIPY]** → пользователь увидит «Файл больше 8 МБ», а не молчаливую отправку. Отправлять такое в чат amo всё равно вряд ли стоит.
- **[Изменение контракта `Host`]** → затрагивает оба `Host` и все вызовы, но UI вызывает сеть только через `fetchGifs` и `importTelegramSet`, сам `Host` он не трогает.
- **[Проверка `Content-Length` не заменяет потоковую]** → сервер может соврать или не прислать заголовок, поэтому поток читается с лимитом всегда.
- **[`localhost` пропал из боевой сборки]** → разработчик на `localhost:3000` должен собирать через `pnpm watch`; это описывается в `CLAUDE.md`.

## Migration Plan

Миграций данных нет, схема IndexedDB не меняется. Откат — revert PR.
