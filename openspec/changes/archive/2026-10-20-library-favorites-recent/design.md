## Context

Файл `.amostickers` — zip с `manifest.json` (`LibraryManifest`: `format`, `version`, `packs`) и GIF стикеров в
`stickers/<n>.gif`. Выгрузка (`libraryFile/exportLibrary.ts`) пишет только паки; чтение (`readLibraryFile.ts`) строит
`LibraryFile` с `entries` — записью архива по id стикера, карточку (`compareWithLibrary` / `loadFileCard`) по id паков и
стикеров библиотеки, подготовка (`prepareImport.ts`) проверяет GIF новых стикеров и строит `ImportPlan`, а
`writeImport` (`db.ts`) одной транзакцией на `packs` и `stickers` читает состояние и пишет записи из чистой
`buildImportRecords` (`libraryFile/importRecords/`). Гард `parseManifest` игнорирует неизвестные поля, а `limits.ts`
прямо говорит: новое необязательное поле версию формата не поднимает.

Избранное — хранилище `favorites` с `FavoriteRec { key, ts, item }` (у стикера ещё `sticker` — снимок `StickerRec` с
GIF), недавние — `recent` с `RecentRec { key, ts, item }`, ключ обоих — `itemKey` (`l:<id>` / `r:<источник>:<id>`),
лимит недавних — `RECENT_LIMIT = 40` на вид (`recentOverflow`). Лента недавних стикеров показывает только те, чей стикер
есть в библиотеке.

Решения пользователя (issue #134): избранное и недавние несёт только выгрузка библиотеки; они в ней всегда, без флажка,
а дока и пояснение группы предупреждают, что файл библиотеки личный; загрузка объединяет.

## Goals / Non-Goals

**Goals:**

- Перенос избранного (стикеры и GIF, в том числе избранный стикер удалённого пака) и недавних (обоих видов) файлом
  библиотеки, слиянием, атомарно с паками.
- Обратная совместимость в обе стороны без новой версии формата.
- Те же гарантии недоверенного файла, что у паков.

**Non-Goals:**

- Избранное и недавние в «Выгрузить пак».
- Выбор при выгрузке «с историей / без».
- Перенос настроек, режима попапа, признака показанной инструкции импорта.
- Изменение схемы IndexedDB.

## Decisions

### Описание: два необязательных раздела верхнего уровня

```ts
type ManifestFavorite =
  | { kind: 'sticker'; id: string; ts: number }                        // стикер есть в паке файла
  | { kind: 'sticker'; id: string; ts: number; file: string;           // стикер со своим GIF
      packId: string; emoji?: string; caption?: string }
  | { kind: 'gif'; ts: number; gif: ManifestGif };

type ManifestRecent =
  | { kind: 'sticker'; id: string; ts: number }
  | { kind: 'gif'; ts: number; gif: ManifestGif };

type ManifestGif = { provider: 'giphy' | 'klipy'; id: string; title?: string; url: string; previewUrl: string;
                     width: number; height: number };

type LibraryManifest = { format; version; packs: ManifestPack[]; favorites?: ManifestFavorite[];
                         recent?: ManifestRecent[] };
```

`FORMAT_VERSION` остаётся 1: разделы необязательные, файл прежней выгрузки их не несёт и читается как раньше, а
прежняя версия amo stickers (1.2.0) читает новый файл без них — паки переносятся, избранное и недавние нет. Альтернатива
— версия 2 — отказала бы прежней версии в файле целиком («обновите amo stickers») ради данных, которые она всё равно не
пишет; неполный перенос без ошибки лучше, чем никакого.

Ссылка «стикер есть в паке файла» вместо второго GIF: один GIF не лежит в архиве дважды, а правило «повтор ссылки на
один GIF — ошибка файла» остаётся простым. Избранный стикер со своим GIF несёт `packId` — пак, к которому принадлежал
снимок: запись снимка на новом месте та же, что на старом. Стороны снимка берутся из заголовка GIF, а не из описания, как
у стикеров паков; `createdAt` снимка — время записи импорта (на показ не влияет).

Порядок в массивах — от новых к старым, как их читает лента; порядок на новом месте всё равно задаёт `ts`.

Альтернатива — отдельный `favorites.json` в архиве: второй файл описания со своими пределами и CRC ради данных размером
в килобайты; одно описание проще и проверяется одним гардом.

### Гард разделов

`parseManifest` разбирает разделы, если они есть:

- `kind` — только `sticker` / `gif`, иначе `invalid` (новый вид — новая версия формата);
- id стикера — `TELEGRAM_STICKER_ID_RE` или `CUSTOM_STICKER_ID_RE`; у снимка `packId` — `custom` или `tg:<имя набора>`
  по тем же правилам, что id пака, вид id стикера согласован с видом `packId`;
- `ts` — `optionalTime`, но обязательный;
- GIF: `provider` из двух, `id` — непустая строка до 128 символов, `title` урезается до `MAX_TITLE_GRAPHEMES`, `url` и
  `previewUrl` — строки до 2048 символов, проходящие `isAllowedUrl` (`@core/net`: `https` и хосты политики), стороны —
  `isDimension` (`@shared/guards`);
- повторы: ключ элемента (`itemKey`) в избранном, ключ в недавних — `invalid`; `id` и `file` снимка — в общих множествах
  `isUnique` со стикерами паков: снимок с id стикера пака файла или с чужим `file` — `invalid`;
- недавних каждого вида — первые `RECENT_LIMIT` после сортировки по `ts`, остальное отбрасывается (как урезание
  строк); избранного — не больше `MAX_FILE_FAVORITES` (10 000), больше — `tooBig`;
- снимки считаются в `MAX_FILE_STICKERS` вместе со стикерами паков (`countStickers`);
- ссылки без своего GIF (избранный и недавний стикер, которого нет в паках файла) отбрасываются без ошибки — как обложка
  не из пака;
- `empty` — только когда нет ни стикеров паков, ни избранного, ни недавних после отбрасываний.

`readLibraryFile` кладёт записи архива снимков в тот же `entries` по id: id снимка не пересекается с id стикеров паков.

### Выгрузка

`exportLibrary` для библиотеки дочитывает `listFavorites()` и недавние обоих видов (`listRecent`) — без транзакции с
чтением паков, как и сейчас: выгрузка — снимок «примерно сейчас». Избранный стикер, id которого есть среди выгружаемых
стикеров, пишется ссылкой, иначе — снимком со своим GIF в `stickers/<n>.gif` после стикеров паков. Недавний стикер —
только если его id среди выгружаемых. GIF-элементы — из `item.gif`, название урезано пределом формата; GIF, которую
загрузка не примет (ссылка длиннее 2048 или не `isAllowedUrl`, сторона не `isDimension`), молча пропускается: одна
битая запись базы не роняет выгрузку всей библиотеки, а файл не несёт того, что гард не прочитает. Свой манифест, как и
сейчас, проходит `parseManifest` до сборки архива.

`checkLimits` считает и снимки: ход и итог — по всем GIF стикеров файла, предел `MAX_STICKER_BYTES` — и для снимков
(ошибка без названия пака — `error.libraryFile.favoriteGifTooBig`). Пустота — нет ни стикеров, ни избранного, ни
недавних GIF (недавние стикеры без стикеров невозможны).

Кнопка «Выгрузить библиотеку»: `useStickerCount` → `useExportableCount` по `countExportable()` в `db.ts` — сумма
`count()` стикеров, избранного и диапазона ключей недавних GIF (`r:`…`r;`, как `countFavoriteStickers`), пересчёт ещё и
на смену избранного (`useFavoritesContext().favorites`). Пояснение недоступности и текст группы — новые строки словаря.

### Карточка

`LibraryState` получает `favoriteKeys: ReadonlySet<string>` и `recent: readonly RecentRec[]` — записи недавних целиком,
а не карту ключ → `ts`: их же принимает `mergeRecent`; `loadFileCard` читает ключи избранного (`listFavoriteKeys`,
`getAllKeys` — без снимков с блобами) и `getAll` недавних (`listAllRecent`, не больше 80 мелких записей). `compareWithLibrary` добавляет в `FileCard`:

- `newFavorites` — элементы избранного файла, ключей которых нет в `favoriteKeys`; у снимка — признак, что его GIF нужно
  проверить;
- `recentAdds` — элементы недавних файла, которые после слияния окажутся в первых 40 своего вида и которых нет в
  недавних или которые там старше, — чистая `mergeRecent(existing, incoming)` из `libraryFile/`, её же берёт запись;
- `newFavoriteCount`, `newRecentCount`.

«Всё уже в библиотеке» — `newStickerCount + newFavoriteCount + newRecentCount === 0`; `runFileImport` заканчивает импорт
по тому же условию. Итог карточки — прежняя строка о паках и, если есть, строка об избранном и недавних: часть с нулём
не пишется — «В избранное: N, в недавние: M» (`add.file.listsSummary`), «В избранное: N» (`add.file.favoritesSummary`)
или «В недавние: M» (`add.file.recentSummary`); при нуле новых стикеров строка о паках не показывается.

Недавний стикер считается добавляемым, только если стикер будет в библиотеке: он в паке файла (тогда он в библиотеке
или будет записан). Это уже гарантирует гард: ссылки на стикеры вне паков файла отброшены.

### Подготовка и записи

`prepareImport` проверяет ещё GIF снимков из `card.newFavorites` (те же `checkSticker`), ход «N/M» — по сумме новых
стикеров и снимков. План получает `favorites: ImportPlanFavorite[]` (у снимка — проверенный `ImportPlanSticker` и
`packId`) и `recent: ManifestRecent[]`.

`writeImport` открывает транзакцию на четыре хранилища: `packs`, `stickers`, `favorites`, `recent`. Чтение — ещё ключи
избранного, все недавние и записи стикеров, на которые ссылается избранное плана без снимка (`stickers.get(id)` — снимок
избранного стикера, уже лежащего в библиотеке, берётся из его записи). `buildImportRecords` строит ещё:

- записи избранного для ключей, которых нет: снимок — запись стикера из этой же транзакции (записываемая или
  прочитанная), а для снимка из файла, id которого в библиотеке занят, — прочитанная запись библиотеки; ссылку, для
  которой записи нет (стикер не записан и не прочитан), — пропуск;
- слияние недавних `mergeRecent`: что записать (`put`) и какие ключи удалить сверх лимита.

Одна транзакция сохраняет гарантию «либо всё, либо ничего». `ImportWritten` получает `favoriteCount` и `recentCount`.

### Исход

`finishFileImport`: раздел для перехода — `«Избранное»`, если добавлены избранные стикеры, иначе `«Недавние»`, если
добавлены недавние стикеры и раздел будет показан, иначе первый пак по `firstAddedSection`. Статус — «Добавлено
стикеров: N», а при `N = 0` — `status.fileImportListsDone` «Избранное и недавние добавлены». Провайдер после записи
перечитывает ещё избранное (`refreshFavorites`) и недавние — они меняют обе ленты.

## Risks / Trade-offs

- **Прежняя версия читает новый файл молча без избранного** → это и есть цена совместимости; пользователь, у которого
  одна версия на обоих концах (автообновление), этого не встретит. В доке — без отдельной оговорки.
- **Файл библиотеки раскрывает историю отправок** → решение пользователя: всегда в файле; пояснение группы «Библиотека»
  и дока направляют делиться файлом пака.
- **Недавние GIF ссылаются на внешние адреса** → те же ссылки, что лежат в базе; гард пропускает только адреса сетевой
  политики, а скачивание идёт прежним путём с её проверкой.
- **Транзакция шире** → избранное и недавние малы (килобайты, до 80 записей недавних); блобы снимков — те же стикеры,
  что и так пишутся.
- **Карточка недавних считает «после слияния в первых 40»** → чуть сложнее «нет ключа», зато «Всё уже в библиотеке» не
  врёт, когда файл несёт только старые недавние, которые вытеснило бы лимитом.

## Migration Plan

Схема базы и версия формата не меняются; миграции нет. Откат — прежняя сборка: её чтение проигнорирует новые разделы.
