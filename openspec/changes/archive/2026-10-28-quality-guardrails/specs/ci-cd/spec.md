## MODIFIED Requirements

### Requirement: Проверки PR
Для каждого PR в `master` система SHALL запускать девять отдельных проверок: линт (eslint, prettier, неиспользуемый
код, правила кода проекта, конфиги агентов), проверку типов, юнит-тесты, сборку обеих целей с бюджетом размера, сборку
сайта доки, проверку версии, проверку workflows, поиск секретов и поиск уязвимостей в зависимостях. Каждая проверка MUST
отображаться в PR отдельным статусом, упавшая проверка MUST давать статус «failure». Новый push в ветку PR MUST
перезапускать проверки и отменять незавершённый прогон по предыдущему коммиту.

#### Scenario: Ошибка линта
- **WHEN** в PR попадает файл, не проходящий `prettier --check`
- **THEN** проверка линта в PR падает, остальные проверки выполняются и показывают свой результат

#### Scenario: Упавший тест
- **WHEN** в PR есть падающий юнит-тест
- **THEN** проверка тестов в PR падает

#### Scenario: Битая ссылка в доке
- **WHEN** в PR страница доки ссылается на несуществующую страницу доки
- **THEN** проверка сборки доки в PR падает

#### Scenario: Все проверки зелёные
- **WHEN** код PR проходит линт, типы, тесты, сборку, сборку доки, проверку версии, проверку workflows, поиск секретов
  и поиск уязвимостей
- **THEN** все девять проверок в PR успешны

#### Scenario: Новый коммит в PR
- **WHEN** в ветку PR пушится новый коммит, пока проверки предыдущего ещё идут
- **THEN** прогон по предыдущему коммиту отменяется, проверки идут по новому
