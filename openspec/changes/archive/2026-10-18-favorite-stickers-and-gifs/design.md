## Context

Мотивация — в proposal.md, требования — в specs/.

Библиотека — IndexedDB `amo-stickers` версии 1 с хранилищами `packs`, `stickers`, `recent` (`src/core/db.ts`).
`onupgradeneeded` создаёт все три без ветвления по версии, обработчиков `blocked`, `versionchange` и ошибки версии нет;
`openDb` ленивый — вкладка открывает базу при первом чтении. Недавние — записи `{ key, ts, item }` с ключом
`l:<stickerId>` / `r:<provider>:<id>` (`recentKey`), до 40 каждого вида.

Лента стикеров: `useFeedSections` читает библиотеку и недавние на каждое открытие и на смену `packs`, чистая
`feedSections` строит разделы — недавние (`RECENT_SECTION_ID`, `pack: null`) и паки. Ряды ленты ключуются номером ряда
(`StickerFeed`, `key={from + offset}`): раздел, выросший или исчезнувший выше, пересоздаёт кнопки ячеек ниже. `FeedRow` по
id раздела решает, что удаляет меню ячейки (`CellRemoveKind`) и какой пак отмечать отправкой (`packId`). Вкладка без пака
— `ClockIcon` (`SectionTabs`), действие заголовка — `headerAction(sectionId)`, у неизвестного id — меню пака. Фокус после
удаления — чистые `cellRemovalTargets` / `sectionRemovalTargets` и `useStickerRemovalFocus` поверх `useRemovalFocus`.

Лента GIF: `useRecentGifs` читает недавние GIF, чистая `gifSections` строит разделы `{ id, title, items, skeletons,
isRecent }` — недавние только без запроса, заголовок трендов только под недавними. Раскладка (`splitColumns`) — плитки
`tiles` с `top` и `total`, без верхов разделов; раздел без заголовка своей плитки не имеет. `MasonryCell` даёт меню
удаление по `onRemove`; фокус — `useGifRemovalFocus`, знающий только раздел недавних, с запасными целями «поле поиска» и
«Открыть настройки» без ключей. Ветка без ключей в `GifView` рисует ту же сетку с недавними.

Меню ячейки: `cellMenuItems(kind)` → `['preview']` или `['preview', 'remove']`, `CellMenu` рендерит пункты `switch`-ем.
Значение `PickerContext` не мемоизировано и `memo` в ленте нет: любое изменение провайдера (статус, отправка)
перерисовывает все ячейки — они потребители `usePicker()` через `useCellSend`.

Загрузка на открытие (`useOpenLoad`) вызывается в `Picker.tsx`, а не в провайдере: настройки, свой пак, паки. Режим
первого открытия (`startMode`) выбирается по `countStickers()`.

Отправка стикера (`app.ts`, `toFile`) берёт запись `getSticker(stickerId)`; записи нет — `SendError` «стикер удалён».
Object URL ячеек кэшируются по id стикера (`useObjectUrls`): кэш по id отдаёт прежний URL для любого блоба, удаление
стикера и пака отзывает URL `dropUrl`.

## Goals / Non-Goals

**Goals:**

- Одно хранилище избранного для обоих видов и одна проверка «в избранном ли» по тому же ключу, что у недавних.
- Избранный стикер самодостаточен: картинка и метка имени файла не зависят от библиотеки.
- Библиотека не зависает молча ни при каком состоянии других вкладок.
- Чистые функции разделов, лимита недавних и удержания прокрутки — с тестами.

**Non-Goals:**

- Ручная перестановка, лимит числа и синхронизация избранного.
- Живое обновление избранного из другой вкладки при открытом попапе — только при следующем открытии.
- Удержание прокрутки при других перечитываниях ленты (импорт, удаление, открытие) — только при правке избранного.
- Пункт избранного в предпросмотре и у превью черновика.
- Обновление снимка избранного стикера при повторном импорте пака: пока стикер есть в библиотеке, показывается и
  отправляется запись библиотеки, снимок нужен только без неё.

## Decisions

### Хранилище `favorites` и версия базы 2

Новое хранилище `favorites` с `keyPath: 'key'`, `DB_VERSION = 2`. `onupgradeneeded` создаёт каждое хранилище, только
если его нет (`db.objectStoreNames.contains`): одна ветка работает и для новой базы, и для обновления с версии 1, без
переписывания существующих записей.

Запись — размеченное объединение по виду элемента:

```ts
type FavoriteRec = { key: string; ts: number } & (
  | { item: LocalSendItem; sticker: StickerRec } // снимок записи стикера на момент добавления
  | { item: RemoteSendItem }
);
```

Ключ — тот же, что у недавних: `recentKey` переименовывается в экспортируемый `itemKey(item)`. Поэтому «в избранном
ли» для любой ячейки — `keys.has(itemKey(item))`, и тот же стикер Telegram после удаления и повторного импорта пака
(id `tg:<file_unique_id>` стабилен) узнаётся как избранный. `put` по ключу и `delete` по ключу идемпотентны: пункт,
выбранный по состоянию, устаревшему из-за другой вкладки, приводит запись к выбранному состоянию без дубля и ошибки.

Функции `db.ts`: `listFavorites()` (от новых к старым по `ts`), `putFavorite(item, sticker?)`, `deleteFavorite(item)`,
`getFavoriteSticker(stickerId)`, `countFavoriteStickers()`.

Альтернативы:

- Флаг на записи стикера — не переживает удаление пака и не годится для GIF, у которых записи нет. Отвергнута.
- Избранное в хранилище `recent` с префиксом ключа — без новой версии базы, но прежний код во вкладке, ещё не
  обновлённой, посчитал бы такие записи недавними: показал бы их и вытеснял лимитом. Отвергнута.
- Снимок только ссылкой на стикер (без блоба) — избранное пропадало бы с паком; решено иначе (issue #87).

### Открытие базы: один запрос на вкладку

Запросы `indexedDB.open` к одной базе стоят в общей очереди: новый запрос ждёт, пока не обработан прежний. Поэтому
заблокированный запрос не бросается и не повторяется — повтор встал бы за ним и висел без событий.

Модуль держит состояние открытия: нет запроса, запрос идёт, запрос заблокирован, соединение открыто.

- **Нет запроса** — `openDb` создаёт запрос; ожидающие вызовы получают его исход.
- **`blocked`** — вкладка прежней версии держит соединение версии 1 и на `versionchange` его не закрывает. Состояние
  становится «заблокирован», ожидающие вызовы и каждый следующий `openDb` сразу отклоняются
  `LocalizedError('error.db.blocked')`. Запрос остаётся в очереди: когда та вкладка обновится или закроется, его
  `success` делает соединение текущим, и следующее открытие попапа читает библиотеку без перезагрузки вкладки.
- **`error`** — `VersionError` (базу уже обновила более новая версия amo stickers из другой вкладки) становится
  `LocalizedError('error.db.outdated')`, прочие ошибки — как есть; состояние сбрасывается в «нет запроса».
- **`versionchange`** у открытого соединения — более новая версия просит базу: соединение закрывается, состояние —
  «нет запроса». Следующий `openDb` этой вкладки получит `VersionError` → `error.db.outdated`: «Перезагрузите вкладку».

Ошибки доходят до строки статуса обычным путём: `useOpenLoad` и чтения лент показывают их `showError` на каждом
открытии попапа. Вкладка прежней версии, которая базу ещё не открывала, обновлению не мешает, а после него получит
сырой `VersionError` своего кода — это вне власти новой версии, частые вопросы доки советуют перезагрузить вкладку.

### Контекст избранного

`useFavorites` в провайдере держит записи (`null` — ещё не прочитаны), множество ключей, `refreshFavorites()` и
`toggleFavorite(item, sticker?)`, и отдаёт их отдельным контекстом `FavoritesContext`. `useOpenLoad` на каждое открытие
запускает `refreshFavorites()` сразу, параллельно цепочке настроек и паков, а не после неё: лента не ждёт настроек
дольше, чем сейчас. Правка из другой вкладки видна при следующем открытии. Сбой чтения избранного — ошибка в статусе и
пустое избранное (или прежнее, если оно уже было прочитано), а не `null`: иначе сбой одного хранилища прятал бы всю
ленту стикеров.

`toggleFavorite` пишет в базу, обновляет состояние и показывает статус «Добавлено в избранное» / «Убрано из
избранного»; сбой записи — `showError`, состояние не меняется. Возвращает, применилось ли изменение: лента по нему
снимает ожидание удержания прокрутки.

Контекст отдельный от `usePicker()`, чтобы ячейки не получали состояние избранного пропом: пункт меню смонтирован,
только пока меню открыто, и читает своё состояние сам, а ряды и ячейки о множестве ключей не знают. Перерисовка ячеек
на правку избранного всё равно будет — правка показывает статус в `PickerContext`; это та же цена, что у любого
статуса, и мемоизация ячеек — не задача этого change.

### Меню ячейки

`cellMenuItems(kind)` возвращает `['preview', 'favorite']` и `'remove'` третьим при `kind`. Пункт `FavoriteItem` читает
`FavoritesContext`: подпись `menu.addFavorite` / `menu.removeFavorite` по наличию ключа ячейки; выбор закрывает меню и
зовёт `onFavoriteToggle` ячейки — без подтверждения, как «Убрать из недавних». У `CellMenu` новые обязательные проп
`favoriteItem: SendItem` и колбэк `onFavoriteToggle`; у `StickerCell` `removeKind` становится необязательным (у
«Избранного» удаления нет). Ячейки (`StickerCell`, `MasonryCell`) прокидывают колбэк через ряды и сетки до режимов
(`StickersMode`, `GifView` в обеих ветках), а те решают фокус и удержание прокрутки и зовут `toggleFavorite`.

### Разделы ленты стикеров и лимит недавних

Разделы считаются синхронно — `useMemo` от прочитанного (`byPack`, недавние) и записей избранного из контекста:
правка избранного пересчитывает ленту без нового чтения базы. Пока избранное не прочитано (`null`), разделов нет, и
«Избранное» не вклинивается в уже показанную ленту на первом открытии.

`feedSections(packs, byPack, recent, favorites)`:

- «Избранное» (`FAVORITE_SECTION_ID = 'favorite'`, `pack: null`) — первым, из записей вида `local`; стикер ячейки —
  запись библиотеки по id, если она есть, иначе снимок (`urlKey` — «Object URL снимка»). Ключ ячейки — ключ записи, как у
  недавних. Нет записей — нет
  раздела.
- «Недавние» — записи, чьих ключей нет в избранном и чей стикер есть в библиотеке, первые 14
  (`RECENT_STICKERS_SHOWN`). Записанные недавние остаются до 40 (`RECENT_LIMIT` в `db.ts` не меняется): убранный из
  избранного стикер возвращается на своё место, а «Недавние» не пустеют от того, что часть последних ушла в избранное.

`headerAction(FAVORITE_SECTION_ID)` — `null`. Вкладка без пака выбирает значок по id раздела: `StarIcon` (новый, по
образцу `ClockIcon` на `TabSvg`) у избранного, часы у недавних. `FeedRow`: у «Избранного» нет пункта удаления и нет
`packId` — отправка из него паки не поднимает. Отправка из «Избранного» пишет недавние как обычно.

Альтернатива — лимит 14 на запись (`RECENT_LIMIT` для стикеров): тогда избранное в недавних съедало бы места, и после
ухода в избранное «Недавние» показывали бы меньше 14. Отвергнута.

### Избранные GIF

`gifSections({ favorites, recent, gifs, term, hasFeed, loading })`: при пустом запросе — раздел избранного
(`FAVORITE_GIF_SECTION_ID`, заголовок `gifs.favorites`), затем недавние без избранных, затем выдача; заголовок трендов —
если выше есть хоть один раздел. Флаг `isRecent` раздела (`GifSection`, `gifSections`, `MasonryGrid`) заменяется видом
`kind: 'favorite' | 'recent' | 'feed'`: по нему `MasonryGrid` даёт удаление и «Очистить» только недавним. Ветка без
ключей в `GifView` получает избранное так же, как недавние.

### Фокус после правки избранного

Цель фокуса ставится на каждую правку, а не только на уход ячейки: ряды ключуются номером, и рост «Избранного» на ряд
пересоздаёт кнопку оставшейся ячейки — фокус, возвращённый меню на источник, упал бы в `body`.

- Ячейка остаётся в разделе (пак, выдача GIF) — цель `[{ kind: 'cell', sectionId, key }]` той же ячейки; после
  перерисовки она находится по `cellId` / `gifItemCellId`.
- Ячейка уходит («Убрать» в «Избранном», «Добавить» в недавних) — цели `cellRemovalTargets` (стикеры); в GIF — соседняя
  ячейка раздела, иначе первая GIF другого из разделов избранного и недавних, иначе поле поиска, без ключей — «Открыть
  настройки». `useGifRemovalFocus` обобщается с раздела недавних на все показанные разделы — список для поиска цели строится по
  разделам `gifSections`, в том числе по выдаче: иначе цель «та же ячейка» трендов или поиска не нашлась бы, и фокус
  ушёл бы в поле поиска.

Фокус переводится, только если он потерян или остался в пикере (`useRemovalFocus`).

### Удержание места ленты

Якорь — первая видимая ячейка, а не верх раздела: в ленте GIF у раздела нет своего верха, а первый избранный GIF
добавляет заголовок трендов внутрь раздела выдачи.

Чистая `keptScrollTop({ prev, next, scrollTop })`, где `prev` — позиции ячеек прежней раскладки `{ id, top, height }` по
порядку, `next` — верхи ячеек новой раскладки по id:

- `scrollTop === 0` — `0`: лента в начале остаётся в начале, и новое «Избранное» видно;
- иначе первая ячейка `prev`, видимая хотя бы частично (`top + height > scrollTop`) и есть в `next`, — прокрутка
  сдвигается на разницу её верхов;
- такой ячейки нет — прокрутка прежняя.

Позиции ячеек дают чистые помощники по раскладкам: у стикеров — из рядов (`top` ряда, id — `cellId(sectionId, key)`),
у GIF — из плиток `kind: 'item'` (id — `gifItemCellId`). Ячейки удаляемого элемента нет в `next`, и якорем становится
следующая видимая.

Применяется только к пересчёту, вызванному правкой избранного. Лента ставит метку ожидания (`ref` с прежними позициями
и прокруткой) перед `toggleFavorite`; `useLayoutEffect` после новой раскладки ставит `scrollTop`, сразу зовёт
`syncScroll()` (окно рядов считается по новой прокрутке в том же кадре, ряды не пустеют) и снимает метку. Метка
снимается и без применения: когда `toggleFavorite` вернул «не применилось» и при закрытии попапа, — иначе следующая
смена раскладки (импорт, открытие) применила бы устаревший сдвиг. `ModePanel` восстанавливает прокрутку только при
смене режима и с этим не пересекается.

### Отправка избранного стикера без библиотеки

`toFile` в `app.ts` для `local`: `getSticker(id)`, иначе `getFavoriteSticker(id)`; нет обоих — прежний `SendError`.
Метка имени файла берётся из найденной записи — снимок хранит `caption` и `emoji`, имя то же, что из пака.
`SendItem` не меняется: ячейка не знает, удалён ли стикер библиотеки, и не должна.

### Object URL снимка

Ключ URL решает `feedSections`: у ячейки (`FeedSticker`) новое поле `urlKey`, которое `FeedRow` передаёт в `urlOf` вместо
`sticker.id`. Ячейка «Избранного» со стикером из библиотеки получает id стикера — URL общий с ячейкой пака. Со снимком —
`fav:<id>`: кэш по id отдал бы URL блоба библиотеки, отозванный удалением пака, и картинка снимка не показалась бы до
закрытия попапа.

### Режим первого открытия

`startMode` получает число стикеров библиотеки и избранных стикеров: если все паки удалены, а избранный стикер есть,
попап открывается в «Стикерах».

## Risks / Trade-offs

- [Вкладка прежней версии блокирует обновление] → ошибка с подсказкой на каждом открытии и открытие библиотеки, как
  только вкладка обновлена; вкладки этой версии будущим обновлениям не мешают.
- [Вкладка прежней версии, не открывавшая базу, после обновления] → её код покажет сырой `VersionError`; частые вопросы
  советуют перезагрузить вкладку.
- [Откат релиза на версию без избранного] → прежний код не откроет базу версии 2 (`VersionError`), библиотека станет
  недоступна до возврата новой версии. Откат — только новой версией вперёд, не возвратом старого пакета.
- [Снимок дублирует блоб стикера] → до 2 МБ на избранный стикер сверх библиотеки; лимита числа нет, объём растёт по
  числу избранных, а не отправок. Принято.
- [Удержание прокрутки и виртуальное окно] → сдвиг и `syncScroll` в layout-эффекте до отрисовки; проверка — стенд,
  сценарии «Место ленты при правке избранного».
- [Открытие базы без юнит-тестов] → в тестах нет IndexedDB; состояние открытия проверяется на стенде двумя вкладками.

## Migration Plan

Версия базы 2 создаёт пустое хранилище `favorites` при первом открытии новой версией; паки, стикеры и недавние не
трогаются. Откат — см. риски.
