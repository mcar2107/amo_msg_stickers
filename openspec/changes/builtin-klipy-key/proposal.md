## Why

Поиск GIF работает, только если пользователь сам заведёт ключ GIPHY или KLIPY и вставит его в «Настройки» (issue #42).
Для большинства пользователей это барьер: после установки режим «GIF» показывает только подсказку про ключ. Ключ в
бандле публичен, поэтому встроить можно не любой: продовый ключ KLIPY рассчитан на клиентский код, бесплатный и без
лимита запросов, а у GIPHY бесплатный ключ ограничен 100 запросами в час на всех пользователей сразу, продовый — платный.
Поэтому встраивается только KLIPY, по образцу встроенного токена Telegram-бота (#83).

## What Changes

- Сборка подставляет встроенный ключ KLIPY из переменной окружения `KLIPY_API_KEY` в бандлы content script и
  userscript. Без переменной ключа в сборке нет, и поиск ведёт себя как сейчас. Значение с пробелами внутри или
  символами вне `[A-Za-z0-9_-]` роняет сборку текстом без самого значения.
- CI: шаг `pnpm build` получает секрет репозитория `KLIPY_API_KEY`; `ci.yml` объявляет его в `workflow_call.secrets`,
  `release.yml` передаёт явно. PR из форка и Dependabot секрета не получают — их сборка без ключа. Ключа нет в git.
- Источник «KLIPY» в режиме «GIF» доступен со своим ключом или встроенным; запросы идут по своему ключу, а без него — по
  встроенному. GIPHY — как сейчас, только со своим ключом. Подсказка «нужен API-ключ» — только когда нет ни своих ключей,
  ни встроенного.
- Встроенный ключ не показывается в «Настройках» и не пишется в хранилище: поле KLIPY — только для своего. Проверка ключа
  у поля — только своего.
- «Настройки» при встроенном ключе: подпись поля KLIPY говорит, что свой ключ необязателен; подсказка — что поиск KLIPY
  работает и без него, а свой нужен, если встроенный недоступен; пояснение группы «GIF» — что ключ GIPHY добавляет
  источники GIPHY, а не «хватит одного из двух».
- Отказ KLIPY встроенному ключу (HTTP 401, 403, 404 — ключ отозван, 429 — лимит) показывается ошибкой «встроенный ключ
  KLIPY недоступен, укажите свой в настройках», а не сырым `HTTP <код>`.
- Дока на обоих языках: «Ключи GIF» — поиск KLIPY работает сразу, свои ключи необязательны (GIPHY — для источников
  GIPHY, свой KLIPY — если встроенный недоступен); главная, частые вопросы и README — без обязательного ключа; политика
  конфиденциальности — KLIPY получает встроенный ключ или ваш.

### Modified Capabilities

- `gif-search`: источник KLIPY доступен по встроенному ключу, свой ключ важнее, подсказка про ключи — только без своих
  и встроенного, отказ встроенного ключа с подсказкой задать свой.
- `runtime-hosts`: подпись и подсказки поля KLIPY и пояснение группы «GIF» зависят от наличия встроенного ключа;
  хранится и проверяется только свой ключ.
- `ci-cd`: сборка в CI и релиз несут встроенный ключ KLIPY из секрета, сборка без секрета — без него, битое значение
  роняет сборку.
- `user-docs`: раздел ключей GIF без обязательного ключа, политика конфиденциальности о встроенном ключе.

## Impact

- Сборка: `build.mjs` (`define` ключа, проверка формата, строка «есть / нет» в лог), чистая проверка в `scripts/`,
  `src/types.d.ts` (объявление константы), `vitest.config.ts` (значение константы в тестах).
- Ядро: модуль встроенного ключа в `src/core/`, `src/core/sources/gifs.ts` (доступность источника, выбор ключа, отказ
  встроенного ключа), `SettingsView` (подпись, подсказка, пояснение группы), словари `messages.ru.ts` / `messages.en.ts`.
- CI: `.github/workflows/ci.yml`, `.github/workflows/release.yml`. Нужен секрет репозитория `KLIPY_API_KEY` с продовым
  ключом KLIPY — его заводит владелец репозитория.
- Дока: `docs/content/setup/gif-keys.md`, `index.md`, `faq.md`, `privacy.md` и их пары в `docs/content/en/`; `README.md`.
- `CLAUDE.md`: сборка, CI и внешние данные.
- Схема настроек и IndexedDB не меняются, миграций нет. Версию PR не поднимает: минор выйдет PR релиза.
