# Внешние данные и сетевая политика

Проверка всего, что пришло извне: хосты, лимиты, гарды, встроенные токен и ключ, файл выгрузки.

Граница — `core/net.ts`; ошибки политики, лимита и HTTP общие для всех окружений, политика и лимит — `LocalizedError`
(отказ SW — на языке amo, `i18n.md`).

- **Хосты** — только `https`: `api.telegram.org` точно, `giphy.com` и `klipy.com` с поддоменами, по разобранному `URL`
  и снова по итоговому адресу после редиректа. SW отвечает только content script-ам своего расширения.
- **Ответы** — `fetchJson` отдаёт `unknown`, сужают гарды `sources/*.types.ts`: непригодный элемент выдачи или ссылка
  вне политики отбрасывается, битый ответ — ошибка источника.
- **Версия GIF** (`sources/gifs.ts`) — по весу из выдачи (`size`: строка у GIPHY, число у KLIPY): самая тяжёлая ≤ 2 МБ,
  иначе самая лёгкая ≤ 8 МБ, иначе самая лёгкая. Кандидаты от крупной к мелкой (GIPHY `original` … `fixed_width_small`;
  KLIPY `gif`, `mediumgif`, `tinygif`, `nanogif` — их же просит `media_filter`), равный вес — первая. Вес — не поле
  формы: без весов у всех — по имени (`downsized`, затем `original`; `gif`, затем `tinygif`).
- **`fetchBlob(url, maxBytes)`** — поток с обрывом на лимите (в расширении — в SW): GIF из поиска 8 МБ
  (`MAX_REMOTE_GIF_BYTES` — вес из выдачи может быть неизвестен или врать), файл Telegram 5 МБ. У менеджера потока нет:
  `abort()` по `Content-Length`, `loaded` в `onprogress`, иначе на `onload`. Не-2xx важнее лимита: `HTTP <код>` с тем,
  что успело прийти.
- **`fetchJson`** — ≤ 2 МБ (`MAX_JSON_BYTES`); у менеджера ещё размер текста в байтах UTF-8 на `onload`. Тело не-2xx —
  ≤ `ERROR_BODY_MAX_BYTES` (800 байт = 200 символов UTF-8), но на заголовках обрыв только по `maxBytes`, иначе текст
  ошибки остался бы без начала тела.
- **Telegram** — `resolveTelegramSet`: битая ссылка и нет токена — ошибка без запроса, набор проходит гард и идёт и в
  карточку, и в `importTelegramSet`. `file_path` без `..`: иначе URL схлопнется, и запрос с токеном уйдёт в другой метод
  Bot API. `.tgs` — ≤ 8 МБ распакованным и `isLottieJson`; GIF из поиска — `inspectGif`.

## Встроенные токен Telegram и ключ KLIPY

Публичны в бандле (сборка — `build.md`): достать и тратить лимиты можно, риск принят. Утечка — перевыпуск в @BotFather
или Partner Panel KLIPY, смена секрета, патч-релиз; до него пользователь уходит на свой по ошибке отказа встроенного.
Встроенного GIPHY нет: бесплатный общий — 100 запросов в час на всех, продовый платный.

Свой важнее встроенного (`klipyKeyOf`; источник KLIPY есть в `availableFeeds` при любом из двух; `noToken` — без обоих).
Встроенные в `DEFAULT_SETTINGS` не кладутся — иначе автосохранение записало бы их в хранилище; `SettingsView` по
константам меняет только тексты, `checkGifKey` проверяет только свой. Отказ встроенного —
`error.telegram.builtinUnavailable` (401/429 у `getStickerSet`, `getFile`, скачивания; импорт останавливается, уже
импортированное остаётся) и `error.gifs.builtinUnavailable` (`KEY_REJECT_STATUSES.klipy` или 429; в статусе «GIF:» и на
пустой ленте). Остальное и любые ошибки своего — как есть. Статус — `httpStatus` из текста `httpError`, а не класс:
граница SW передаёт ошибку текстом.

## Файл выгрузки `.amostickers`

Недоверенные данные: его мог собрать кто угодно. Всё проверяется до первой записи в базу.

- **Zip** — срезы `Blob`, каждое смещение сверяется с размером файла. Записей без `__MACOSX/` — ≤ `MAX_ZIP_ENTRIES`;
  от 4 ГиБ или заведомо больше записей — «слишком большой» до чтения каталога; deflate обрывается на размере из
  каталога и лимите GIF (zip-бомба); CRC-32 сверяется.
- **`manifest.json`** (≤ 16 МБ) — `parseManifest`: формат и версия (новее — совет обновиться), `source` и `id` пака
  согласованы (имя ≤ 64, как у Telegram), id стикеров — `tg:` у Telegram, без него у своих. Повтор пака, стикера или
  ссылки на GIF — ошибка; длинные строки урезаются по графемам (`clampGraphemes`), чужая обложка отбрасывается.
- **GIF** — ≤ 8 МБ, `inspectGif`, стороны — `gifScreenSize`, а не из описания.
- Выгрузка прогоняет свой манифест через тот же гард: не сохранит то, что не прочитает.
