# Пикер: оболочка

Shadow DOM, фасад `createPicker`, провайдеры, режимы и экраны, формы, движение, a11y и тема — перед правкой любого
кода в `src/core/ui/`.

## Карта модулей

Всё — в `src/core/ui/`, компоненты и хуки — каталогами в `Picker/` (`@ui/…`).

- **Оболочка.** `createPicker.tsx` — фасад для `app.ts`; `picker.css` — вход Tailwind, сброс наследования `:host`,
  кольцо фокуса, `.feed-scroll`, `.scroll-fade`; `icons.ts` — svg кнопки в DOM amo; `renderMessage/` — строка словаря
  с узлами Preact на месте подстановок. `Picker.tsx` — панель: оба режима, экран поверх, строка статуса, футер.
- **Провайдеры.** `PickerProvider/` — `usePicker()`: окружение, настройки, паки, статус, отправка, удержание, object
  URL, импорт из Telegram и из файла, выгрузка (ходы — чистые `runPackImport/`, `runFileImport/`, `runLibraryExport/`);
  в нём же отдельный контекст избранного `useFavorites/`. `usePickerView/` — режим, экран, цель фокуса экрана
  (`screenFocus.ts`), якорь ленты стикеров, режим первого открытия (`startMode.ts`).
- **Режим «Стикеры»** — `StickersMode/`, `SectionTabs/`, `StickerFeed/`, `stickerLayout/`, `PackCover/`; **«GIF»** —
  `GifView/`, `useGifFeed/`, `MasonryGrid/`, `ViewHeader/`. Общее у лент — `keptScrollTop/`, `revealScrollTop/`,
  `elementById/`, `isFocusLost/`, `SectionHeader/`, `Menu/`, `useConfirmPress/`, ячейки (`StickerCell/`, `cellName/`,
  `useCellSend/`). Подробно — `picker-feeds.md`.
- **Предпросмотр** — `Preview/`, `pressGesture/`, `usePressPreview/`, `useCellPreview/`, см. `picker-preview.md`.
- **Экраны** — `Screen/` (оболочка экрана), `AddView/`, `SettingsView/`, `Field/`, см. `picker-add.md`.
- **Примитивы** — `Button/`, `TextInput/`, `EmptyState/`, `StatusBar/`, `TabSvg/`, `CellSpinner/`, `ExternalLink/`
  (ссылка подсказки в новой вкладке), `LinkButton/` (переход между экранами), `moveTabFocus/`, `scrollMotion/`,
  прочие `use*/`.

## Shadow DOM и хосты

Хост пикера вставляется внутрь кнопки: `position: fixed` считается от предка с transform — контейнера поля ввода, как
у попапа эмодзи. Где встаёт панель и какой она высоты, решает разметка — `amo-dom.md` («Где встаёт панель»). Shadow
root разделяет CSS amo и пикера (preflight Tailwind не трогает страницу); корень `closed` — на «Настройках» ключи
GIF и токен бота, `element.shadowRoot` их не отдаст.

Второй хост — слой предпросмотра (`previewElement`): `div` со своим `closed` shadow root в `document.documentElement`, а
не в `body` — слежение ядра и amo за `body` его не будит. `fixed` во всё окно, максимальный `z-index`,
`pointer-events: none`: из панели страницу не накрыть, `fixed` там считается от контейнера поля. Дерево слоя —
отдельный `render()` со своим `<style>` и обёрткой `dark` (`picker-preview.md`).

## Фасад и контексты

`app.ts` живёт без Preact и зовёт `createPicker(host, { onSend, onClose, onHoldRelease })`: `open`, `close()`,
`setTheme(isDark)`, `isHeld()`, `isOpen`, `isClosing`. Фасад перерисовывает `render()` на каждое изменение, а закрытый
пикер остаётся смонтированным — режим, прокрутка лент и запрос поиска переживают повторное открытие. Данные и действия —
`usePicker()`, режим, экран и якорь — `usePickerView()`. Избранное — `useFavoritesContext()`: записи (`null` до первого
чтения), множество ключей, `refreshFavorites`, `toggleFavorite(item, sticker?)`; его читает пункт меню, а ряды и ячейки
о ключах не знают. Занятость отправки — в ячейке (`useCellSend`): повторное нажатие не шлёт второй стикер, соседи
доступны, занятая — `disabled` с `CellSpinner/` поверх.

## Режимы и экраны

Футер (`Footer/`) — переключатель «Стикеры» / «GIF» и «Настройки». Оба режима смонтированы всегда (`ModePanel/`),
неактивный — `display: none`: поиск и выдача переживают переключение, а сбрасываемую скрытием прокрутку панель помнит
и возвращает. Режим пишется в `localStorage` страницы (`pickerMode.ts`); без него или при сбое чтения — «Стикеры», если
есть стикер в библиотеке или избранный стикер, иначе «GIF» (`startMode.ts`). Экраны «Добавить стикеры» и «Настройки»
лежат оверлеем: режим под ними `inert` и в раскладке, «Назад» возвращает его с той же прокруткой и поиском.

**Экран** (`Screen/`) — `<section aria-labelledby>` на своём `h2`: строка с заголовком (обрезается) и «Назад», тело с
прокруткой и необязательный футер вне прокрутки с главной кнопкой (у «Настроек» его нет). С `shouldFitBody` тело —
колонка flex, свободную высоту делит растущее содержимое, прокрутка — когда не влезает и его наименьшая высота (сегмент
«Файл»). Экран рендерят сами `AddView` и `SettingsView`. При монтировании фокус — в первое видимое доступное текстовое
поле (`useScreenFocus`); повторное открытие попапа и смена сегмента фокус не трогают. Цель фокуса передаёт точка входа —
`openScreen(screen, { focus })`, элемент несёт id из `SCREEN_FOCUS_ID`: фокус без прокрутки браузера, тело
прокручивается по геометрии (`focusScrollTop`) — прокрутка по фокусу и `scrollIntoView` задели бы страницу amo.

Высота футера — константа `SCREEN_FOOTER_HEIGHT_PX` (числом: Tailwind не ищет классы в `.ts`), и строка статуса встаёт
над ним без замера (`StatusBar` с `isRaised`, есть ли футер — `hasScreenFooter.ts`). Live region остаётся одним узлом
панели: область, появившаяся вместе с текстом, не объявляется. Высоту строки статуса замеряет `ResizeObserver`
(`StatusBar/useHeightReport/`) в переменную `--status-inset`: на неё растёт нижний отступ тела экрана; лента режима
раскладку не меняет.

**Формы.** Тело — `<form id onSubmit>` с `preventDefault`, кнопка футера — `type="submit" form={id}` вне формы: Enter
отправляет, а недоступная кнопка неявную отправку блокирует силами браузера, без своих обработчиков клавиш. `Field/`:
`<label htmlFor>` даёт имя, слот `labelAside` — кнопка после `<label>`, вне его; ошибка, результат проверки и подсказка —
id в `aria-describedby` (`TextInput.describedBy` — через пробел), ошибка — ещё `aria-invalid`; скрытое значение (ключи,
токен) — значок глаза в поле, имя «Показать» / «Скрыть», `aria-pressed`. Шрифты: заголовок экрана — `text-sm
font-semibold`, группы — `h3` `text-xsm font-semibold`, поля — `text-xsm`.

## Движение

Появление — переход из `[@starting-style]:`: панель режима после `display: none`, строка статуса при появлении плашки,
меню — только после замера места (вариант `isPlaced` в `Menu/`), иначе мигнуло бы в углу. Экран — прозрачность и сдвиг
8 px анимацией скрипта (`element.animate()`) при монтировании, `key={screen}` — и при смене экрана: `@starting-style`
проигрывался бы на каждом открытии попапа (экран смонтирован, панель скрыта `display: none`). «Назад» играет её обратно
с текущего места за 100 мс и закрывает экран по концу — до этого режим `inert`. Повторное «Назад» в уходе ничего не
делает; экран, снятый в уходе кнопкой футера, закрытие анимации не задевает; `display: none` анимацию не отменяет —
уход доигрывается, закрытие по отмене — только защита. Меню закрывается сразу. Прозрачность и сдвиг не трогают
раскладку — ввод с первого кадра. Наведение кнопок — через `enabled:`: недоступная его не получает.

Уменьшение движения выключает всё одним вариантом: переход — только под `motion-safe:`, стартовое состояние
`[@starting-style]:` — без варианта. Длительность — тоже под `motion-safe:` (`motion-safe:duration-base` / `-lg`):
`motion-safe:transition-*` несёт свою длительность в `@media`-блоке позже простого `duration-*` и перебивает его.
Скрипт читает настройку в `scrollMotion/` на каждый переход, без подписки: `isMotionReduced()` — экран сразу,
`scrollMotion()` — `'auto'` или `'smooth'`. Спиннер отправки крутится всегда.

## Доступность

Панель — `<dialog>` с `aria-label`. Переключатель режимов и полоса разделов — ARIA tabs: в Tab только выбранная,
стрелки / `Home` / `End` — фокус (`moveTabFocus/`), выбор — Enter, пробел, клик. Режим — в `tabpanel` с
`aria-labelledby` кнопки режима, лента стикеров — в `tabpanel` вкладки активного раздела. Строка статуса — постоянная
live region (`role="status"`) слоем поверх низа ленты: высота ленты не меняется. Кольцо фокуса — только
`:focus-visible` (`@layer base` в `picker.css`). Имена ячеек — целые фразы словаря из `cellName/` («Отправить стикер
«привет»», «Send sticker “привет”»): подпись не переводится.

## Тема и цвета

`resolveDarkTheme` (`amoDom.ts`, чистая): класс `dark` на `<html>`, затем `data-amo-theme="dark"` / `"light"`
(Worker-версия), без обоих — системная тёмная, но только при поле Worker-версии на странице: у прежней amo в светлой
теме нет ни класса, ни атрибута, и системная перекрасила бы пикер. `app.ts` пересчитывает её по `class` и
`data-amo-theme` на `<html>`, `watchSystemTheme`, вставке кнопки и перед каждым открытием и зовёт `setTheme`; корень
получает `dark`, `dark:`-варианты (`darkMode: 'selector'`) работают внутри shadow root. Цвета — только токены
`tailwind.config.ts`, без hex и inline-цветов.
