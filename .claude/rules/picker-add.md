# Экраны «Добавить стикеры» и «Настройки», выгрузка

Импорт из Telegram, свой стикер, импорт и выгрузка файла, автосохранение настроек и проверка ключей. Оболочка экрана и
формы — `picker.md`.

## «Добавить стикеры»

`AddView/` — сегменты «Telegram» / «Свой стикер» / «Файл» (ARIA tabs), подписи — в строку на 350 px на обоих языках.
Выбор — `addSegment` в `usePickerView` (до перезагрузки, не в `localStorage`): «+» — последний выбранный, плитка
«Создать стикер» — «Свой стикер» (`openScreen(screen, { segment })`). Панели смонтированы все, неактивные `hidden` —
ввод переживает смену сегмента. Хуки форм (`useTelegramImport`, `useStickerDraft`) зовёт `AddView`: от них зависит
главная кнопка футера; импорт файла — в провайдере (`fileImport`).

**Фокус после успеха** (Telegram, свой стикер, файл): переход к разделу закрывает экран вместе с кнопкой футера, и фокус
встаёт на вкладку раздела (`scrollToSection` с `shouldFocusTab`) — только если потерян (`isFocusLost/`): ушедший в поле
amo его не теряет.

**Telegram.** Ссылка и ошибка поля — в провайдере (`usePackImport`), переживают закрытие экрана. Ошибка импорта — у
поля, только если в момент прихода открыт этот сегмент, иначе в статус (`importErrorTarget` в `finishImport/`). Ход —
`runPackImport/`, в статусе — только когда сегмента не видно.

**Карточка пака** (`PackCard/`, текст — описание поля): через 300 мс паузы `resolveTelegramSet` через `packPreview/` —
кэш промиса по имени до перезагрузки, отклонённый удаляется; импорт берёт набор оттуда же, `getStickerSet` один раз.
Ответ по устаревшему имени отбрасывается по номеру запроса. «Пак не найден» (400 / `ok: false`, `previewOutcome`) —
ошибка у поля и недоступная «Импорт» (`isPackMissing`); прочий сбой и нет токена — карточка молча убирается, импорт не
блокируется (покажет ошибку сам), повтор — при смене токена (`shouldRequestPreview`). Во время импорта — снимок пака
(`packCardView/`), правка поля его не меняет.

**Отмена.** «Отменить» встаёт вместо «Импорт» тем же `Button` без `key` — фокус остаётся, `type="button"` — Enter её не
жмёт; клик с `detail > 1` (второй клик двойного по «Импорт») игнорируется (`isRepeatClick/`). `AbortController`:
`importTelegramSet` проверяет `signal` перед `getFile`, скачиванием, конвертацией и записью (ответ в полёте
отбрасывается), конвертация — перед кадром и проходом, Worker останавливается. Откат до броска `signal.reason`: новый
пак удаляется, прежняя запись пака и перезаписанные стикеры возвращаются из снимка, новые стикеры удаляются, порядок не
меняется. `onCancel` перечитывает паки, «Импорт отменён» — в статус не ошибкой, ввод и лента не трогаются.

**Инструкция импорта** раскрыта при первом показе сегмента и свёрнута после: признак `importHint.ts` читается при
монтировании экрана, а пишется при показе, а не по успеху — её видел и не доведший импорт; сбой хранилища — раскрыта.
«?» (`HintToggle/`) — в `labelAside`, а не в `<label>`, иначе её имя вошло бы в имя поля; `aria-expanded`,
`aria-controls`, раскрытая инструкция — в описании поля.

**Свой стикер.** Нативное поле файла скрыто, диалог — кнопкой (`input.click()`, удержание `fileDialog` по нажатию): имя
из словаря, без «Файл не выбран» браузера. Превью (`DraftPreview/`) — на всю зону, имя и «Заменить файл» — плашками
поверх, заголовка нет: сегмент влезает в 350×400 без прокрутки. `saveBlock` (`'noFile'` / `'converting'` / `null`;
пауза после правки подписи — уже сборка) — текстом в футере, иначе там размер и вес стикера, а не в статусе. Фокус — в
поле подписи: Enter по привычке не откроет диалог файла.

**Файл.** Выгрузка — в «Настройках» (ссылка `LinkButton/` в заголовке группы ведёт туда с фокусом на кнопке): её группа
не дала бы сегменту влезть в 350×400. `accept` — `.amostickers,.zip`, но файл узнаётся по содержимому. `dragover` и
`drop` дальше зоны не уходят: amo слушает `drop` на `body` и прикрепил бы файл к сообщению. Карточка `ImportCard/`
встаёт на место зоны (слот `card`), перетаскивание зона принимает и с карточкой. Фокус при открытии — на вкладку
сегмента: текстового поля нет.

Раскладка без замера: тело — колонка flex (`shouldFitBody` у `Screen`), форма, блок полей и панель — колонки `grow` без
`min-h-0`, растёт только зона (`basis-31`, `grow`, `max-h-max`), в ней сжимается список паков (`PackList/`). Итог: тело
не прокручивается, пока заголовок, зона наименьшей высоты и ошибка помещаются над строкой статуса, иначе прокручивается,
и ничего не уходит под статус. Край списка затухает (`scroll-fade`, scroll-driven маска; под фокусом с клавиатуры маски
нет). У списка `role="region"` с `tabIndex`, пока есть что прокручивать: область сама встаёт в порядок Tab только с
Chrome 130.

Ошибка чтения — без карточки, записи — под зоной с карточкой (файл остаётся для повтора). Состояние (`useFileImport`:
файл, карточка, ошибка, этап `checking` / `writing`, ход) живёт до успеха или другого файла. Сверка с библиотекой
(`loadFileCard` по `listStickerIds`, без блобов) — при выборе файла, возврате на сегмент и по «Импорт», устаревший ответ
отбрасывается по номеру запроса.

**Импорт файла** — `runFileImport/`: свежая сверка (нечего добавлять — конец), `prepareImport` с ходом и отменой,
`writeImport`. Отмена — только до записи: выданные запросы транзакции коммитятся. На записи «Отменить» —
`aria-disabled`, а не `disabled` (`Button.shouldKeepFocus`), иначе фокус упал бы в `body`; наведение —
`[&:enabled:not([aria-disabled]):hover]:`. Исход (`fileImportOutcome/`): успех — сброс файла и, только при открытом
экране, лента к первому разделу с добавленным (`firstAddedSection`, `'instant'`); сбой проверки — «Импорт» недоступна до
другого файла; сбой записи (`error.libraryFile.quota` / `writeFailed`) — доступна. Ошибка всегда у зоны, а когда
сегмента не видно (`importErrorTarget(screen, segment, importSegment)`), ещё и в статусе: вернувшийся видит, почему
«Импорт» недоступна. Статус дублирует ход вне сегмента (`fileImportStatus`) на каждом шаге, уходе и возврате: запись
хода не сообщает, и ушедший иначе не увидел бы «Запись…». Экран остался, а «Импорт» недоступна — фокус на вкладку «Файл»
(`useImportEndFocus/`).

**Один импорт за раз.** `importLock` провайдера — `ref` с источником (два запуска в одном кадре видят его до
перерисовки), общая причина удержания `import`; пока идёт один, «Импорт» другого недоступна.

## Выгрузка

Пак — `ExportPackItem/` меню «…» (меню закрывается первым), библиотека — `SettingsView/LibraryExport/` (без стикеров
недоступна с пояснением, `useStickerCount/`). Состояние — в провайдере (`useLibraryExport`): меню, ячейки под
виртуализацией и экран размонтируются, а выгрузка доходит до конца. Одна за раз (`ref` и `isExporting`):
`MenuItem.isDisabled` — `aria-disabled`, выбор игнорируется, пункт остаётся в обходе стрелками, чего `disabled` не дал
бы; у кнопки — `shouldKeepFocus`. Ход — `onEntry` у `writeZip`. Итог — только после запуска скачивания
(`runLibraryExport/`); сбой сборки — неполный файл не скачивается. Файл сохраняет `downloadBlob`: адрес блоба отзывается
через `REVOKE_DELAY_MS`, сразу после `click()` отзыв оборвал бы скачивание. Выгрузка не пишет в базу, `usedAt` и
недавние не трогает.

## «Настройки»

Без «Сохранить» и без футера; «Библиотека» (выгрузка) — вне формы. Тексты KLIPY зависят от встроенного ключа
(`klipyKeyText/`): с ним свой ключ необязателен, без него — «хватит одного ключа из двух».

**Автосохранение** (`useSettingsDraft` → `saveSettings`): пауза ввода 600 мс, `focusout` формы, Enter (`change`) и
размонтирование экрана. Пауза — потому что Escape закрывает попап без `blur` поля. Пишется только отличие от
сохранённого (обрезка пробелов, пустое — нет ключа; `settingsDraft/`). Удачная запись статуса не показывает, ошибка — в
статус. `saveSettings` и `refreshSettings` — одна очередь промисов: перечитывание на открытие ждёт запись, правки
смонтированного экрана им не сбрасываются.

**Проверка** — на фиксации, а не на паузу: пауза тратила бы лимит GIPHY. Фиксация — и `focusout`, и `change`: `change`
не приходит при возврате к значению на входе в поле (возврат к проверенному остался бы без результата), а `submit` по
Enter в форме из трёх полей без кнопки не приходит. `checkGifKey` (`sources/gifs.ts`) — один запрос трендов `limit=1`,
не бросает: `ok` / `rejected` (статус из текста ошибки, `httpStatus`) / `unavailable`; отказ — GIPHY 401, 403, KLIPY ещё
404. Токен Telegram — только формат `isBotTokenFormat`, без сети. Проверяется значение, отличное от последнего
проверенного; правка забывает проверенное (`forgetChecked`), устаревший ответ отбрасывается по номеру запроса.
Результат — `fieldCheckText/` в описании поля, тон — `fieldCheckTone/`: принятый — зелёный, отказ — цвет ошибки и
`aria-invalid`.
