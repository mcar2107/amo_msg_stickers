# Язык интерфейса

Выбор языка, словари, где зовётся `t`, ошибки SW, что не переводится — перед правкой `core/i18n/` и строк.

Язык (ru / en, как у amo web) ставит первая строка `start()` — `setLocale(readAmoLocale())` — до перезагрузки:
состояние модуля `translate.ts` без подписок. Код вне `start()` (тесты, SW) получает русский.

**Источник:** `localStorage` `i18nextLng` (`AMO_LOCALE_KEY`) → `<html lang>` → `navigator.languages[0]` (пустой —
`navigator.language`). `<html lang>` — ради Worker-версии: `i18nextLng` она не пишет. При сбое хранилища `<html lang>`
не читается: прежняя amo держит в нём `ru` при любом языке. `resolveLocale`: основной тег `en` (без учёта регистра и
региона) — английский, иначе — русский, запасной язык amo.

**Словари.** `RU` — эталон: из него выводятся `MessageKey` и подстановки `{name}`; `EN: Record<MessageKey, string>` —
пропуск или лишний ключ не компилируется, как и `t` без нужной подстановки. Подстановка без значения остаётся в тексте —
пропуск виден. Префиксы ключей — по месту (`picker.` `add.` `settings.` `menu.` `gifs.` `status.` `error.` …). Строку
со ссылкой внутри собирает `renderMessage/`: фраза — один ключ, на месте подстановки — узел Preact. Библиотеки i18n
нет: два языка без множественных форм её не окупают; строка от числа получит `Intl.PluralRules` здесь же.

**`t` — в рендере и в момент броска**, не в константах модуля: модули вычисляются до `setLocale`, константа застыла
бы на русском. Таблицы подписей держат ключи (`Record<…, MessageKey>`).

**Ошибки SW.** SW языка amo не знает. Ошибки, общие для SW и страницы (политика хостов и лимит из `core/net.ts`), —
`LocalizedError` с ключом и параметрами. Граница — `src/extension/fetchResponse.ts`: `toFailureResponse` кладёт `key` /
`params` только у неё, `unwrapFetchResponse` пересоздаёт её на языке amo, если ключ есть и параметры совпадают с
подстановками, иначе — `Error` с текстом SW. `gmNetwork` живёт в мире страницы и переводит свои ошибки `t` сразу.
Параметры (статус, начало тела, лимит) сохраняются.

**Не переводится:** данные пользователя (подписи стикеров, названия паков Telegram, названия и запросы GIF);
`HTTP <код> <тело>`, сообщения браузера, `fetch failed`, `description` Bot API; «Powered by GIPHY / KLIPY», «GIPHY API
key», «KLIPY API key»; логи и ошибки-инварианты для разработчика. Имя отправляемого файла от языка не зависит
(`feed-style.md`).

**Свой пак** — `packTitle(pack)` по id `custom` → `t('pack.custom')`, а не `title` записи: тот на языке создания, и
переписывать его — миграция базы на смену языка. Пак Telegram — как есть. Любой показ названия пака — через
`packTitle`.

**GIF:** `locale` — последний аргумент функций `sources/gifs.ts`, `useGifFeed` передаёт `getLocale()`. GIPHY — `lang`
только в поиске (у трендов нет), KLIPY — `locale=ru_RU` / `en_US` в поиске и трендах.

**Ссылки на доку** — `userDocsUrl(page, getLocale())` в рендере. Префиксы — `Record<Locale, string>` в `userDocs.ts`
(`ru` — корень, `en` — `en/`).

Строки интерфейса — только через словарь, парой в `RU` и `EN` (правило — в `CLAUDE.md`). Названия, у которых в amo
есть свой перевод («Отправить», «Настройки», «Поиск», «Удалить»), совпадают с ним на обоих языках.
